# 实现调研 · FR-907 前端实时声学反馈（含评审修正）

> 目标：在关卡页（P05）录音发声过程中，基于浏览器 Web Audio API 提供零延迟的前端实时反馈；仅在内存中渲染，不产生网络请求，提交后精细对比仍由后端产出（P09）。
> 需求出处：commit 15bbb41《修正文档》（FR-907、架构文档 §4.1、前端决策图 FD-03）。
> 状态：**已按本文件（含评审修正）实现完毕**；初版调研中的若干判断经评审推翻，修正记录见第二节。

## 一、已有实现盘点（评审时确认仍然成立）

- `src/stores/recorder.ts`：唯一的 `MediaRecorder` 封装（授权、待机、15/40 秒上限、重录、释放、iOS 手势内 resume）。原版已创建 `AudioContext + AnalyserNode`（fftSize 1024）并以 rAF 循环把 RMS 推入响应式数组 `waveform`——这条响应式路径与 1024 点窗口（对 65Hz 男低声不足两个基音周期）是本次改造的两个直接动因。
- `src/components/RecorderPanel.vue`：录音区状态容器，原内联一块 canvas 画 RMS 柱状音量条。
- `src/pages/LevelLearnSection.vue`：P05 接线处（props 透传、`useAssessmentFlow` 状态机驱动录音窗口）。
- `src/components/CalibrationPanel.vue` + `features/calibration.ts`：同一 recorder store 的第二消费方（标定 40 秒，不显示波形）——store 内部改造的主要回归面。
- `src/renderers/VotWaveformChart.vue`、`ToneCurveChart.vue`：事后波形与 F0 曲线的视觉语义参照（数据缺失留空不伪造）。
- `src/stores/player.ts`：全局单音频播放；实时监听不发声、与其无冲突。
- MSW mock 层与本功能无关（纯前端、零网络）。

## 二、初版调研的错误与评审修正

| # | 初版结论 | 评审意见 | 修正后方案（已实现） |
| --- | --- | --- | --- |
| 1 | F0 纵轴「宜直接用 Hz」 | 人耳音高感知是对数的：线性 Hz 会把低音声部压扁、高音声部放大；且没有目标引导带的实时曲线只是「屏保动画」，不是生物反馈 | 纵轴用对数半音标度（55Hz 基准）；有调型时叠加**五度目标引导带**（半透明轨道 + 虚线中心线，1 度 = 3 半音挂靠窗口中心）；纵轴窗口自适应到本人平均音高 ±8 半音（初始 85–320Hz） |
| 2 | 波形 + 音量 + F0 一刀切塞进同一画布 | 声母关练的是送气/摩擦（看包络与频谱），声调关练的是走向（看 F0），全量同屏只会分散注意力 | 主视图按关卡层切换：声母关（layer=initial）主画能量包络 + 谱重心配色，声调/韵母/拼读关主画 F0 轨迹；音量状态灯条常驻顶部 |
| 3 | 在全局 Pinia recorder store 里跑分析循环 | store 应只管录音状态机与产出 Blob；60fps 副作用放全局 store 会污染状态管理，还把分析生命周期强加给 CalibrationPanel 等不需要它的消费方 | store 瘦身：删掉响应式 `waveform` 与自带 rAF，只暴露 `getAnalyser()`；分析与绘制全部收进 `RealtimeAcousticCanvas` 组件（挂载即连、卸载即断） |
| 4 | 手写自相关 + 自修八度跳变 | 手写检测器在强 F1 元音上极易八度错误；pitchy（McLeod Pitch Method，~3KB 零依赖）直接输出 pitch + clarity，清浊门限一行搞定 | 引入 `pitchy`；平滑只做「半音域 3 点中值滤波（剃单帧八度跳变）+ EMA」；clarity ≥ 0.85 且 65–500Hz 才判有声，清辅音/噪声自然留空 |
| 5 | 停止/重录即清空画布 | 停止到提交之间的「本地试听」是最佳教学时刻：应定格整段轨迹，试听时画播放游标，让用户在前端就发现「三声没拐弯」直接重录，省掉后端废调用 | 停止后画布定格整段（横向压缩全时间轴），试听时竖线游标随播放推进；重录/重新开始录音才清空 |

## 三、最终实现结构

- `src/utils/realtimeAcoustics.ts`（纯计算，可单测）：`RealtimePitchTracker`（逐帧 RMS/峰值/截幅 → pitchy 清浊判定 → 中值 + EMA）、`AdaptivePitchWindow`（半音纵轴窗口）、`toneOfPinyin`（关卡拼音声调符号 → 调号，推不出不画引导带）、`toneTargetContour`（四声五度轮廓）、`spectralCentroidHz`（频域能量加权谱重心，带底噪截止）、半音换算。
- `src/components/RealtimeAcousticCanvas.vue`：rAF 驱动（分析按 ~60fps 节流，高刷屏不多算）；原生 Canvas 2D + ResizeObserver + devicePixelRatio；主副双视图（F0 轨迹 + 目标带 / 能量包络 + 清音配色：清音段按谱重心分「偏高频接近平舌 / 偏中低频接近翘舌」，截幅标红、音量偏轻有文案提示）；非响应式帧缓冲，仅低频展示态（音量档、当前 Hz、摩擦频段读数）进响应式并节流。
- `src/stores/recorder.ts`：fftSize 2048（65Hz 男低声含 2 个以上周期）；`getAnalyser()` 之外不新增任何分析职责。
- `src/stores/player.ts`：补 `currentTime/durationSec` 播放进度追踪（rAF ticker），供定格画布的试听游标使用。
- `RecorderPanel.vue`：录音中与已录制两个阶段常驻画布（实时 → 定格 + 游标）；`LevelLearnSection.vue` 按关卡层传 `focus`、按拼音传 `targetTone`。

## 四、保留的工程约束

- 不上 `AudioWorklet`：60fps 单通道 2048 点 MPM 主线程耗时约 0.15–0.4ms，`AnalyserNode.getFloatTimeDomainData` 足够，免去 Worklet 打包与跨线程通信。
- 采集约束维持关闭回声消除/降噪/自动增益（AGC 会放大静音段底噪造成假阳性 F0）。
- 高频数据不进 Vue 响应式；三条清理路径（停止/重录/释放）都终止循环并清状态。
- 依赖新增仅 `pitchy`；测试为合成信号确定性单测（正弦/白噪/静音/八度毛刺/换段断开）。

## 五、与决策图的一处刻意偏差

前端决策图把实时分析职责写在「recorder composable 输出实时帧」上；最终实现按评审意见把分析与绘制收进 `RealtimeAcousticCanvas`（store 只暴露 AnalyserNode）。属职责归属的再划分，对外行为与 FR-907 验收口径不变；若需要文档同步，应更新决策图组件划分表。
