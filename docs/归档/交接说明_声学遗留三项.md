# 交接说明 · 声学相关三项遗留功能差距

> 背景：2026-10-18 完成需求文档简化（commit `ebb2daa`）后的代码对齐清理，以下三项属于文档已要求、但代码尚未实现/未做的新功能，不属于当时的清理范围。需求条目编号以 `ebb2daa` 版本的 `docs/srs/` 为准（该目录仍在持续修订中，动手前请以最新版为准）。

## 一、送气段波形 / VOT 标注对比视图（未实现）

### 需求出处
- `docs/srs/04-功能-账号检测与档案.md` **FR-1005 多维声学可视化对比** 第三条：面向声母（塞音/塞擦音送气对比 `b/p`、`d/t`、`g/k`、`z/c`、`zh/ch`、`j/q` 及擦音 `f/h`、`s/sh/x` 等）以及全部关卡，展示**时域波形（标注送气段 / 嗓音起始时间 VOT）**与宽带/窄带语谱图，让学习者直观看到清辅音摩擦噪声频带、成阻除阻 burst 以及送气段长短的差异。
- `docs/srs/05-功能-CMS与治理.md` **FR-1204**：各关按音素/音节的声学特性配置对应的可视化对比视图（声母关展示送气段波形/VOT 与语谱图），不要求孤立清辅音示范必须提取基频曲线。
- `docs/srs/07-非功能与UI约束.md` 外部接口段：本地声学分析须提取「基频 F0、共振峰 F1/F2、**时域送气段波形/VOT** 与语谱图」。
- `docs/srs/04` 附录 B：录音字段中「声学与评分结果」应包含**送气段波形/VOT 与语谱图资源**。

### 现状（已有什么）
- 语谱图：后端已有整段录音的语谱图 PNG 端点 `GET /api/audio/{id}/spectrogram.png`（`backend/app/api/routes_audio.py`，约 102 行起），由 `backend/app/acoustics/` 基于 parselmouth/matplotlib 渲染；前端 `src/api/mediaUrl.ts` 拼媒体 URL，结果页直接以图片展示。
- F0 / 共振峰：`GET /api/audio/{id}/f0`、`GET /api/audio/{id}/formants`（同文件 69/79 行起）已返回逐帧数据；`AssessmentResult` DTO（`backend/app/api/schemas.py` 的 `ResultCurve`/`ResultFormants`，约 464/489 行）承载按音节分段的曲线与元音空间对比。
- 前端渲染器：`src/renderers/ToneCurveChart.vue`（基频曲线）、`src/renderers/FormantChart.vue`（共振峰），结果页 `src/pages/ResultPage.vue` 中始终展示（清理时已去掉门控）。

### 缺口与建议实现路径
1. **声学侧**：在 `backend/app/acoustics/` 新增送气段/VOT 检测（清辅音起点、burst、嗓音起始的时段划分；可基于能量包络 + 浊音判定，参考 vendored `tone_py` 的有声段检测）。需对**用户录音**与**本关参考示范**双侧计算，才能形成对比。
2. **契约侧**：`AssessmentResult` 扩展 VOT 对比字段（如每音节的 `{user: [start,end], reference: [start,end], votMs}`），或独立端点；`backend/test_openapi_shapes.py` 与前端 `src/api/generated/` 需同步再生成（`npm run api:dump && npm run api:types`）。
3. **前端侧**：结果页新增「送气段波形对比」视图（时域波形 + 送气段/VOT 标注叠加），建议与现有语谱图并排；声母关（`level.layer === 'initial'`）默认展示。
4. 关卡侧如需按音素配置开关，落在关卡检测任务配置（FR-1204）的 `allowedMetrics`/可视化视图配置中。

## 二、FR-1006 结果页「去标定以获得更精准对比」便捷入口（未添加）

### 需求出处
- `docs/srs/04-功能-账号检测与档案.md` **FR-1006 个人音域与元音空间标定（支持跳过）（D-20）** 业务规则：跳过标定时正常受理检测，基频与共振峰采用单次录音自适应范围或默认成人参考范围展示，**并在结果页提供「去标定以获得更精准个人对比」的便捷入口**。

### 现状（已有什么）
- 标定流程完整可用：`src/features/calibration.ts`（读文本→录音→上传 `purpose=calibration`→`POST /api/pitch-calibration`）；`src/components/CalibrationPanel.vue` 在关卡页（P05，`src/pages/LevelLearnSection.vue`）内提供「跳过标定，直接录音」；账号页（P11，`src/pages/AccountPage.vue`）有重新标定入口。
- 标定状态：`src/stores/context.ts` 的 `calibrationValid`（`calibration.status === 'personal'`）。
- 后端：`GET/POST /api/pitch-calibration`（`backend/app/api/routes_audio.py` 约 116/139 行）。

### 缺口与建议实现路径
- `src/pages/ResultPage.vue` 当前**没有**任何去标定引导。建议：当 `calibrationValid === false` 且本次结果的共振峰为 `not_available`（或曲线使用默认范围，见第三项）时，在质量提示卡附近渲染一个入口按钮，行为二选一：
  1. 跳转账号页（P11）标定区（最简单，复用现有入口）；
  2. 或在结果页内嵌 `CalibrationPanel` 折叠区，标定完成后提示可重录对比。
- 纯前端改动，无契约变化。

## 三、未标定时采用默认成人范围，未做逐录音自适应归一化（文档允许二选一）

### 需求出处
- `docs/srs/04-功能-账号检测与档案.md` **FR-1006**：跳过标定时「基频与共振峰采用**单次录音自适应范围或默认成人参考范围**展示」——二选一即可，当前实现取的是后者（合规，非缺陷）；`docs/srs/README.md` **D-20** 同口径。

### 现状（代码位置）
- 后端在受理检测时，若用户无个人音域，用常量 `DEFAULT_ADULT_F0_RANGE`（90–230 Hz）构建本次结果的范围快照（位于 `backend/app/scoring/usecases.py` 的检测受理/音域快照逻辑；常量定义在同文件）。
- 共振峰侧因无个人元音空间，未标定时 `AssessmentResult.formants.status = "not_available"`（`ResultFormants`，`backend/app/api/schemas.py` 约 489 行），符合文档「不伪造」的要求。

### 建议实现路径（如需升级为自适应）
- F0：用户录音的逐帧 F0 已由 `backend/app/acoustics/`（parselmouth/tone_py）提取，可直接取本次录音有声段 F0 的分位数（如 P5–P95）作为归一化范围，替代固定 90–230 Hz 写入范围快照；改动集中在 `scoring/usecases.py` 建快照处，契约不变（`ResultCurve.rangeSnapshotId` 语义照旧）。
- 共振峰：单次录音自适应元音空间意义有限（需要覆盖多个元音），建议维持 `not_available` + 第二项的「去标定」引导，不为跳过标定的单音节伪造归一化空间。
