# 02 · 目标架构

> 范围：SRS 全部 1.0 需求及 2.0/3.0 扩展边界。本文是目标规划，未检查或断言代码已实现。业务以 docs/srs/ 为准，完整 API 以 [后端决策图](../decision-map-backend.md) 为准。

## 1. 部署形态与模块边界

FastAPI 同进程模块化单体 + Vue SPA；SQLite 保存结构化数据/版本，文件系统保存音频与媒体。认证为自研轻量层（用户名/密码 + 服务端会话表），管理界面优先 starlette-admin（sqladmin 备选），单管理员独立认证。单进程单 worker、前端与 `/api`、`/admin` 同源部署。1.0 外部评分为唯一必需业务外部服务；2.0 的本地模型和大模型话术按真实需求接入，不提前引入微服务、消息队列。运行形态与实施步骤见 [03-后端架构与实施方案](03-后端架构与实施方案.md)。

```mermaid
flowchart TB
    UI[浏览器 SPA] --> API[薄 HTTP 契约层]
    API --> Content[content 内容与发布]
    API --> Detection[detection 录音与结果]
    API --> Identity[identity 会话与同意]
    API --> Archive[archive / learning 档案与进度]
    API --> Feedback[feedback 反馈与希望增加]
    Admin[admin 管理界面与预览] --> Content
    Admin --> Feedback
    Detection --> Acoustics[acoustics 音频与特征]
    Detection --> Scoring[scoring 质量与反馈规则]
    Scoring --> Provider[ScoringProvider 协议]
    Provider --> External[外部普通话评分服务]
    Detection --> Archive
    Identity --> Archive
    Archive --> Cleanup[platform 清理与审计]
    Content --> DB[(SQLite / 文件存储)]
    Detection --> DB
    Archive --> DB
    Cleanup --> DB
```

模块拥有自己的数据与用例接口；routes 处理 HTTP 校验/响应，用例编排权限、事务与 IO，纯领域规则处理状态机、质量和反馈判定。跨模块通过用例接口协作，管理员不直接修改已发布版本或私人录音。platform 横切承担 requestId、权限、CSRF、限流、审计和可靠清理。

## 2. 逻辑数据模型

以下为业务模型及持久化边界，不限定具体表名/列实现。

| 对象 | 数据与约束 |
| ---- | ---- |
| Level / Article 身份 | 稳定 id/slug、发布状态、当前公开版本指针、骨架是否预先公开；仅标记预先公开的未发布关可作地图骨架 |
| LevelDraft / ArticleDraft | 可编辑内容、草稿修订号；检测任务/规则/参考示范、构形（内容媒体与声道剖面关键帧）、带稳定 ID 的听辨题与练习步骤属于关卡草稿；与公开版本分离 |
| LevelVersion / ArticleVersion | 不可变快照、版本、发布人/时间/原因；关卡快照含任务、规则、示范、授权引用及发布时预计算的标准曲线；回退创建新发布记录 |
| ReferenceSpeaker | 参考发音人及其登记的音域与元音空间，用于把参考示范换算为标准曲线 |
| Category / Media | 分类及文章公开分类快照、媒体用途/归属/授权/发布引用；私有授权材料不公开 |
| Audio | audioId、所有者 sid/账号、用途、内容哈希、格式、时长、文件引用、首次上传时间、expiresAt、删除状态 |
| Recording | recordingId、audioId、所属关卡公开版本、ruleVersion、提交时间、submissionId、状态（processing/completed/failed）与 stage、attempt、归属、session/archived、consentId、有效期 |
| AssessmentResult | 质量两维、分数、现象、四步、按音节分段的曲线及缺失状态、共振峰（归一化）、Provider/模型版本、音域与算法快照、内容/规则版本；质量不合格不填分数/现象 |
| User / Session | 用户名、密码哈希、服务端认证会话表、数据代次 dataEpoch；独立匿名 sid，登录绑定/退出与访客重置轮换；注销失效全部会话 |
| ConsentDecision | 只追加 granted/rejected/revoked 决定、文案版本（1.0 单一版本）、时间、操作引用；当前状态从历史派生（无记录为未处理） |
| PitchCalibration | 音高音域与元音空间；会话临时或个人；个人音域 = 标定基线 + 最近存档合格录音，记录来源以便删除重算；同意转存时会话标定升级为个人；版本快照供结果引用 |
| LearningEvent | 仅登录且同意后新增，eventId 去重、关卡/内容版本、listen_quiz（questionId、选项、派生对错）或 practice_done（stepId）；进度按 D-24 只读派生，不独立覆写 |
| Feedback / Wish | 情境、文字、处理状态、受控结果/版本引用；删除私人数据时去引用，不复制录音 |
| Feature / Scoring cache | 权限所属、音频内容/版本/算法/音域键、有效期；删除源数据级联清除，不跨账号共享私人缓存 |
| Audit / Deletion record | 操作与状态骨架、requestId、版本、清理状态；撤回/注销后匿名化，不保留私人内容 |

同一用户多次录音可复用音频，但删除须按有效引用判定，禁止物理删除另一个仍有效档案的文件；删除共享缓存引用需同时保证被删 recordingId 不可读取。未引用上传与临时录音均 72 小时，不存在「提交一次就永久转正」。

## 3. 状态与访问

内容三态：草稿 → 已发布 → 已下架；已下架可再次发布，均检查前置条件。已发布内容允许同时存在编辑草稿；重新发布成功原子替换公开版本，失败保留原版本。版本回退不改写历史快照。正常已发布关检测就绪；独立开关仅作应急熔断，故障可见且有审计，冻结时全部已发布关可测。L30 与 L01/L09 的导航关系不是额外发布依赖。

同意状态：未处理 / 已同意 / 已拒绝 / 已撤回；决定只追加。登录只绑定当前 sid 的临时录音；登录且同意有效时自动转存本会话全部未过期、未删除记录，重复操作不重复建档。注册不构成登录，登录不构成同意。退出/切换账号轮换 sid，断开旧账号关系；共用设备同意前须明确转存范围，允许先删除或重置访客会话。

所有录音、audioId 文件/特征/图片/结果读取共享权限：临时数据当前 sid 或绑定账号匹配且未过期；已存档仅本人账号；访客资源一旦绑定账号，sid 单独不再授予访问。不可猜测 ID 仅减少枚举，不替代权限。管理员预览只授权绑定草稿及媒体，不能读私人录音。公开内容每次校验发布引用；地图骨架不带正文/媒体/任务。

## 4. 检测与一致性

```mermaid
sequenceDiagram
    participant UI as P05/P08
    participant API as 检测用例
    participant Audio as 音频模块
    participant Provider as 评分 Provider
    participant Store as 结果/档案
    UI->>Audio: multipart 上传，登记归属及 72 小时 expiresAt
    Audio-->>UI: audioId
    UI->>API: audioId / levelId / contentVersion / submissionId
    API->>API: 校验归属、有效期、有效音域、当前公开版本、检测状态与幂等
    API->>Audio: 解码及信号维质量
    alt 信号不合格
        API->>Store: 保存质量失败快照，不填分数
        API-->>UI: 200 QUALITY_FAIL 与重录指引
    else 信号合格
        API->>Provider: 指定文本评估，复用返回判断朗读维与评分
        API->>API: 朗读质量闸门；合格后规则四步与可用曲线
        API->>Store: 重校验同意/删除状态，写不可变版本快照
        API-->>UI: 质量与结果（曲线按受理时音域快照）
    end
```

检测采用短同步 + 超时回落 202：受理后约 8 秒内完成即同步返回，否则返回 202（recordingId、stage、Retry-After），评分在进程内有界执行器继续，客户端断开不取消；自受理 30 秒未完成标记可重试失败（504），进程重启把遗留处理中记录同样处理。相同所有者+submissionId 同负载重放，不同负载 409，处理中 202，可重试失败同键重新执行；重放校验当前归属与删除状态，但不重算已有版本结果。首次与重试的 requestId 不同，原业务操作可追溯。完成写入前重校验删除、过期、dataEpoch 与同意，任一变化即丢弃结果。

不同 submissionId 提交相同音频，按所有者+规范化 PCM 哈希+内容/规则+Provider/模型版本复用评分结论，确保分数/现象/四步可重复；瞬时 Provider 失败允许重试，不固化为成功缓存。音域/算法版本影响曲线，快照记录当时基准，历史结果不因新标定重算。标定是检测的强制前置：无有效音域时提交返回 409 CALIBRATION_REQUIRED 且不建记录；无有效 F0 为 not_available。结果的主对比曲线与共振峰随结果快照下发，前端只渲染；标准曲线在发布时由参考示范预计算并随版本冻结；本人录音的原始 F0、共振峰及图片按 audioId 对外读取，与音频文件共用归属/失效校验。公开示范与私人上传的授权不同。可重试失败的同键重试只在提交页面内进行，跨页面只提供重新录音。

ScoringProvider 隔离服务差异、指标与音节检错；实际服务维度及乱读/漏读规则须逐关验证，禁止需求层预设所有维度都准确可用。Provider 不可用返回处理失败，不静默换本地模型出分。2.0 专属模型对比按 FR-1604，大模型只改写管理员确认的话术（FR-1601/1602），不修改质量、分数、现象。

## 5. 进度与数据生命周期

访客/未同意进度只在前端本地，服务端不收 sid 学习事件；同意后只上传新的事件（eventId 幂等），不自动导入历史本地进度。服务端按版本验证题目与选项，派生正确性，进度由有效学习事件按 D-24 计算（全部听辨题各至少答对一次 + 全部练习步骤各至少完成一次，录音不计入）；前端本地进度使用同一规则。推荐只用同意有效数据，访客/未同意由前端按本地进度计算，无进度回落 L01/第一已发布关。

私有未存档上传、录音/结果、临时标定与缓存从首次上传起最多 72 小时，不续期；已存档保留至用户删除。撤回立即停止保存并拒绝读取被删资源，再删除账号全部临时/长期录音、结果、文件、特征/评分缓存、学习事件/进度和音域；注销同范围且校验密码/失效全部会话。单删/清空档案不等于撤回，独立学习事件保留，基于被删录音推算的音域须重建或失效。

清理在同部署内调度，幂等重试与监控；到期/用户删除立即逻辑失效，最迟 24 小时完成本地硬删。备份默认不含私人音频/特征，启用时默认最长 7 天，恢复前重放删除记录；第三方留存和删除按实际条款核实。删除/撤回与在途评分或转存并发时禁止数据复活；审计仅保留匿名化操作骨架。

## 6. 前端契约与 CMS

大众端为 SRS P01–P06、P08–P11 共 10 页，前端分层、路由与关键流程见 [04-前端架构与实施方案](04-前端架构与实施方案.md)。P04 使用分类/文章列表/文章详情；P03 使用公开地图骨架加本地或授权进度；P01/P06/P08 过滤未发布骨架。搜索使用服务端 /api/search；P05/P08 复用同一录音编排；P09 按 recordingId 恢复（含 202 处理中轮询），P10 使用 /api/me/recordings 及本人同关 compare；同意前的当前会话临时记录与清空使用 /api/session/*。context 对访客开放，不能为初始化页面强制查询受保护的 /me/progress；context 中的 dataEpoch 用于清除其他设备上已撤回账号的本地数据。

后台 /admin 配置单管理员鉴权，草稿编辑、前置检查、对比、发布/下架、应急检测熔断、版本回退、分类迁移、授权媒体、反馈/希望增加、标定文本和审计通过用例完成。后台签发短期（默认 15 分钟）预览令牌，绑定管理员会话、对象和草稿修订，前端真实 /preview 页面（令牌以 query 传递）读取同结构草稿与受控媒体；后台 Markdown 预览同样打开该页面，全站只有一套渲染；修改修订或退出后失效。分类更名与文章归属不得穿透草稿立即公开。

JSON camelCase 与标准 HTTP、envelope/requestId；文件、Range 与缓存原生响应。OpenAPI 自动生成前端 TS；身份/公开状态每请求重校验，限流覆盖上传/评分/特征/标定/反馈/注册/登录，受控并发与 Origin/CSRF 校验保障资源及写操作。
