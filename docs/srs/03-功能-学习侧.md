# 功能需求 · 学习侧

## 首页与页面总则

#### FR-201 页面结构保留且承载真实内容（1.0，必做）

系统应保留《02-内容模型与信息架构》4.1 节定义的页面结构，页面数量可随版本扩展；每页按其定义承载内容，页面数据来自 CMS 已发布关卡。

#### FR-202 四个主按钮（1.0，必做）

系统应在首屏提供四个主按钮，文案固定为：**搜一个音 / 看懂发音 / 跟着练 / 录音比较**。

业务规则：

- 「搜一个音」进入搜索。

- 「看懂发音」默认进入 P04，并在 P04 内提供进入 P03 已发布层的入口。

- 「跟着练」进入下一已发布关（FR-205）关卡页的练习区。

- 「录音比较」进入检测中心（P08）并预选下一已发布关，录音后在 P09 与标准曲线对比；若当时无已发布关，显示暂无已发布内容。

#### FR-203 搜索框提示（1.0，必做）

系统应在首页搜索框提示可输入汉字、拼音或关卡名，例如「a」「妈」「翘舌」。

#### FR-204 已发布关列表（1.0，必做）

系统应只列出 CMS 中状态为「已发布」的关卡。

#### FR-205 推荐起始关（1.0，必做）

系统应默认从当前进度的下一已发布关开始（完成判定见 D-24）。登录且同意时使用服务端进度；未登录或未同意时使用本设备本地进度（不上传）；无任何进度时从 L01（a）开始，若 L01 未发布，则从当前公开顺序中的第一已发布关开始。

#### FR-206 站点说明（1.0，必做）

系统应在首页底部用短句说明：这是普通话发音学习；结果仅供学习参考。

## 搜索（P02）

#### FR-301 可搜索汉字、拼音、关卡名（1.0，必做）

系统应支持搜索汉字、拼音、关卡名。

#### FR-302 结果字段（1.0，必做）

系统应在每条结果给出关卡名称、类型（单韵母 / 声母 / 拼读）、一句话结论、进入关卡按钮。

#### FR-303 结果范围（1.0，必做）

搜索结果仅包含已发布关卡。

#### FR-304 无结果时的相近关推荐（1.0，必做）

系统应在无结果时给出相近已发布关（例如搜「ai」时给出 a 或相关已发布关），并提供「希望增加」提交口。

## 发音地图（P03）

#### FR-401 三层闯关定位图（1.0，必做）

系统应将发音地图实现为闯关定位图，固定三层：单韵母（L01–L06）→ 声母（L07–L29）→ 拼读（L30）。

#### FR-402 未开放状态（1.0，必做）

地图中尚未发布的层位与关卡仅展示预先公开的身份骨架与「未开放」状态；已发布关可点进。骨架不包含一句话结论、示范、草稿正文或检测任务。是否预先公开由管理员按关在 CMS 标记，未标记的未发布关（如后续版本筹备中的新关）不出现在地图中。

#### FR-403 易混关并排入口（1.0，必做）

系统应提供易混关并排入口：n 与 l、b 与 p、d 与 t、g 与 k、j 与 q、z 与 zh、c 与 ch、s 与 sh、f 与 h、u 与 ü。仅显示双方都已发布的比较。

#### FR-404 地图不承载专业说明（1.0，必做）

发音地图只展示关卡身份、层位、开放状态与进度；发音部位等专业说明位于关卡页专业折叠区（FR-610），默认折叠。IPA 属于 3.0 内容（FR-1701），1.0 不展示。

## 发音原理（P04 · 博客式子站）

P04 为博客式原理子站——文章目录（`/principles`）+ 文章页（`/principles/:slug`），按「气 / 声 / 口型」三分类组织（分类可扩展）。文章讲普遍原理，不枚举具体发音；具体音的讲解全部在关卡页（P05），自 P06 卡片、搜索或地图进入。

#### FR-501 原理子站结构（1.0，必做）

系统应以文章列表与文章页的形式组织发音原理内容，初始分类为「气 → 声 → 口型」三步写清：气从哪里来、声音怎么响、嘴和舌头怎么摆；文章面向普遍原理，不按关卡枚举具体发音。

#### FR-502 短练习与已发布关入口（1.0，必做）

系统应在每篇文章配可跟做的短练习，并链到已发布的相关关卡（例如口型类文章链到 L01–L06 中已发布者）。

#### FR-503 专业句默认折叠（1.0，必做）

系统应将文章中的专业句（部位名称、气流通道、声带细节等）默认折叠，需要时可展开查看。

#### FR-504 教学内容来源与文章级缺席（1.0，必做）

系统应仅使用教学 / 语音学方提供的文字与图；缺材料的文章不发布，且不阻塞其他文章与整站。

#### FR-505 文章配可播放示范（1.0，必做）

系统应保证每篇已发布文章至少有一个可播放示范。

#### FR-506 文章参考资料（1.0，必做）

系统应在文章页提供参考资料条目：标题、来源、许可、适用边界，并链到至少一关已发布关卡。

## 关卡页（P05）

所有关卡与检测页面统一采用「结论 → 示范 → 听辨与练习 → 录音→ 结果 → 下一步」的认知顺序；专业术语默认折叠。

#### FR-601 统一关卡页结构（1.0，必做）

系统应将 P05 作为关卡页。每一关使用同一套结构，不按音临时改版式。

#### FR-602 一句话结论（1.0，必做）

系统应在打开关卡时先展示本关最重要的一件事，例如「这一关把嘴张大，发出 a」。

#### FR-603 构形多视图（1.0，必做）

系统应以可来回切换的多视图呈现构形，让学习者看见嘴、舌等与本关相关的样子：内容媒体（图 / 动图 / 视频）、声道剖面图、三维模型三种视图并存切换。

业务规则：

- 内容媒体与声道剖面图两种视图为 1.0 必做；声道剖面图由 CMS 录入的声道剖面参数（附录 A）驱动绘制。三维视图 1.0 预留切换位，本关无三维模型时按缺席处理，至迟 2.0 补齐。

- 任一视图缺席时其余视图仍可正常查看；构形内容材料可用仍是发布前提（FR-1203）。

#### FR-604 示范音（1.0，必做）

系统应至少提供正常语速可播放示范，鼓励另提供慢速；建议男女声各一条；音频能完整播完。

#### FR-605 跟着练（1.0，必做）

系统应提供短练习。每步可播放、可暂停、可重做；用户可标记「完成这一步」，该标记记为一次练习完成事件（按步骤 ID），用于 D-24 完成度。

#### FR-606 听辨练习（1.0，必做）

系统应提供听辨练习：听一个音、从选项中选出是哪个（例如「nán 还是 lán」）。选择后立即判对错，答错展示解释并允许再答；每次作答记一次听辨事件。系统记录对错，用作学习进度参考（D-24）。未登录或未同意时只记在前端本地；登录且已同意后才向服务端提交新的学习事件，每个事件带 eventId 去重，不自动导入之前的本地进度。

#### FR-607 小测（2.0，必做）

系统应提供几道围绕本关目标的小测题目，记录结果作为本关完成度参考。

业务规则：1.0 不做小测（D-13）；2.0 提供小测，题型以单选起步；1.0 的关卡完成度由听辨与练习事件派生。

#### FR-608 误区（1.0，必做）

系统应用学习者能观察的话说「可能听起来像什么、可以怎么改」，避免病理化表述。

#### FR-609 本关录音入口（1.0，必做）

系统应在每个已发布关提供关卡内录音入口，与 P08 进入同一任务、同一套评分口径。

#### FR-610 专业折叠与相关关（1.0，必做）

系统应将专业术语、来源、适用边界默认折叠，并给出上一关、易混关、下一已发布关。L30 须提供回到 L01 与 L09 的关系；目标未发布时显示不可用状态，不产生可进入的链接。

## 发音库（P06）

P06 是已发布关目录。

#### FR-701 只索引已发布关（1.0，必做）

系统应按单韵母 / 声母 / 拼读分层，只索引当前已发布关。

业务规则：P06 是目录与比较工具页（卡片、试听、任意两关比较），不承载学习进度；进度呈现归 P03。

#### FR-702 卡片字段（1.0，必做）

系统应使卡片含名称、拼音、代表汉字（若有）、示范播放、进入关卡。

#### FR-703 已发布关比较（1.0，必做）

系统应支持选择两个已发布关并排比较示范与构形。P03 的易混关入口与 P05 的易混关链接直接打开该比较；P06 可任选两个已发布关比较，并以易混关作为快捷选项。三处使用同一比较界面与规则。

## 反馈与内容扩展

#### FR-1501 学习页反馈（1.0，必做）

系统应在学习页（至少 P04 文章页、P05 关卡页）提供「看懂了 / 还不明白」，并可写不清楚的位置。

#### FR-1502 结果页反馈（1.0，必做）

系统应在结果页提供「结果是否符合实际感受」以及哪里不理解。

#### FR-1503 希望增加（1.0，必做）

系统应在搜索无结果或页面提供「希望增加」的音或字提交口。

#### FR-1504 纠错（1.0，必做）

系统应支持报告文字、声音、图片、字幕错误。

#### FR-1505 新增关沿用既有结构（1.0，必做）

系统应保证新增已发布关使用同一套关卡页，并保留已有检测任务和档案中的历史记录。

## 读取与反馈契约

搜索由服务端统一匹配汉字、拼音、关卡名并给出相近已发布关；1.0 不增加搜索词持久化日志，「希望增加」由客户端随提交带 searchQuery。P01/P06 过滤地图骨架，仅展示已发布摘要。P04 分类、文章列表及文章详情分别读取，单篇独立发布与缺席。

反馈按情境携带 articleSlug、levelId 或 recordingId；结果反馈的 rating 表达用户实际感受，纠错 subtype 区分文字、声音、图片、字幕。服务端校验私人 recordingId 归属并补齐内容/规则版本；管理员处理视图仅看到反馈文字及版本骨架，不获得录音访问权限。删除录音后反馈去除私人结果引用，禁止借反馈保留录音副本。
