# 功能需求 · 关卡维护与后台（CMS）

## 定位与范围

1.0 的后台（CMS）定位为**团队内部自用的轻量级内容维护工具**，核心目标是方便团队成员以可视化表单的方式录入、修改关卡数据、原理文章和媒体资源。后台修改保存后即可直接生效，供前端页面读取展示。

## 关卡内容与检测配置

#### FR-1201 三十关身份与顺序（1.0，必做）

系统应按《02-内容模型与信息架构》3.4 节关卡清单实现 L01–L30 的身份、顺序和类型；支持按团队实际内容准备进度将关卡设为开放或未开放。

#### FR-1202 已开放关提供学习与录音检测（1.0，必做）

系统应在关卡设为开放后，在关卡页（P05）同步展示学习内容与本关录音检测区。

#### FR-1203 关卡基本内容完整性（1.0，必做）

每个开放关卡应具备完整的教学与检测配置：

- 关卡 ID、顺序、目标音、代表汉字、听辨题和 3–5 步练习。
- 可正常播放的示范音频，以及可用的构形展示材料（内容媒体、2D 声道剖面参数或 3D 模型资源）。
- 常见发音误区说明及语音学/声学参考说明。
- 本关录音检测配置（见 FR-1204）。

#### FR-1204 检测任务配置要求（1.0，必做）

每关可配置朗读提示词、评测文本、参考示范音频及四步反馈模板：

- 评测文本采用评分服务可评测的汉字或带调音节形式（如声母关以代表音节朗读，如 `b` 关读「波」）。
- 各关根据音素/音节的声学特性配置对应的可视化对比视图（如韵母与声调关展示基频 F0 曲线与元音空间共振峰 F1/F2；塞音、塞擦音、擦音等声母关展示送气段波形/VOT 与语谱图）。不要求孤立清辅音示范必须提取基频曲线。

#### FR-1205 评分服务与声学提取（1.0，必做）

系统通过外部普通话评分服务结合本地 Python 声学特征分析（提取 F0、F1/F2、时域波形与送气段、语谱图）完成每关录音评估，并结合规则引擎生成现象与四步反馈。

## 团队自用维护后台

#### FR-1401 关卡字段录入与编辑（1.0，必做）

后台应提供直观的表单界面，支持团队成员按关卡字段（《02-内容模型与信息架构》附录 A）新增或修改关卡文字、声道剖面关键帧参数、听辨题、练习步骤及四步反馈模板，保存后即时更新。

#### FR-1402 媒体文件上传（1.0，必做）

后台应支持上传示范音频、构形图片/动画/视频、三维模型资源及字幕文字，并关联到对应关卡或文章。

#### FR-1403 配置检测任务与标定文本（1.0，必做）

后台应支持为每一关配置朗读提示词、评测文本、参考示范音频、声学可视化指标及四步反馈模板，并支持维护全局的音域标定朗读文本。

#### FR-1404 关卡开放状态切换（1.0，必做）

后台应支持一键切换关卡的「已开放 / 未开放」状态；切换后首页、搜索（P02）、发音地图（P03）和发音库（P06）同步反映最新状态。

#### FR-1407 用户反馈与「希望增加」查看（1.0，必做）

后台应支持查看用户提交的纠错反馈与「希望增加」的音/字记录，并可标记处理状态（待处理 / 已采纳 / 暂不采纳），方便团队根据反馈直接修改对应关卡或补充新内容。

#### FR-1409 原理文章与分类维护（1.0，必做）

后台应支持创建、编辑和删除 P04 发音原理文章及分类。文章支持使用 Markdown 编写正文，并配置标题、slug、分类、摘要、参考资料。

## 实现说明

- 后台可基于轻量级 Python 管理面板或简洁的内部管理页面实现，直接操作数据库表与本地媒体目录，免去复杂权限控制，追求人类维护的高效与便捷。
- 系统支持通过种子脚本（Seed Data）初始化默认关卡与文章数据，也支持在后台界面中直接增删改查。
