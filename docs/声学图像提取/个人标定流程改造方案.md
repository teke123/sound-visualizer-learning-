# 个人元音空间与音域标定方案

## 目标与产物

用户分别录制 `i / u / a / ü` 四个单元音和一段自然朗读短文。每个元音采集两条有效录音，重复结果分散时采集第三条。短文单独录制一条。全部录音完成后生成一份个人标定结果，供后续发音分析、声调五度值换算和元音空间图使用。

标定结果包含：

- 个人音域 `fLo`、`fHi`，来源为短文录音。
- `i / u / a / ü` 各自的 `F1 / F2 / F3` 均值与标准差，来源为对应元音的多条录音。
- `speaker_max_formant`、`overall` 的 `F1 / F2` 归一化参数、每个元音参与计算的录音数、算法版本及完成时间。

完整结果写入现有个人标定记录和录音受理快照。每条练习录音使用提交时冻结的音域及元音空间；`P02_tone_vowel_norm.png` 从同一快照绘制个人元音四边形。

## 录音任务

| 顺序 | 页面文字与发音 | 有效录音数 | 单条目标时长 | 用户操作 |
| --- | --- | --- | --- | --- |
| 1 | 衣 `yī [i]` | 2，必要时第 3 条 | 稳定元音约 0.5–1.0 秒 | 自然、平稳地延长元音；每次独立开始、停止、试听、提交 |
| 2 | 乌 `wū [u]` | 2，必要时第 3 条 | 同上 | 同上 |
| 3 | 啊 `ā [a]` | 2，必要时第 3 条 | 同上 | 同上 |
| 4 | 迂 `yū [y]`，界面写作 `ü` | 2，必要时第 3 条 | 同上 | 同上 |
| 5 | 音域朗读短文 | 1 | 自然语速约 15–30 秒 | 按页面文字连续朗读，独立录音、试听、提交 |

短文由后台配置和版本化，覆盖四声及轻声，约 40–80 个汉字。可采用以下初始文本并标注逐字拼音：

> 今天早上，我带着朋友走过公园的小路。远处有人在唱歌，孩子们一边说笑，一边追着风筝跑。回家以后，我喝了口水，慢慢讲起路上的事情。

录音以 44.1 kHz、单声道、16-bit PCM WAV 存储；浏览器采集后沿用音频上传接口进行服务端规范化。每条元音、短文分别上传并获得独立 `audioId`。前端按任务设置录音时长上限，短文沿用 40 秒上限。

## 前端流程

`CalibrationPanel` 展示当前任务、已完成数量和下一步操作。每次录音都可试听、重录、提交；提交后显示该条录音的验收结果。元音的两条录音各占一个步骤，后端返回 `additional_take_required` 时出现第三次录音步骤。页面记录已验收的任务状态，刷新或重新打开后从服务端继续。主动重新标定与练习前的首次标定共用这一流程。

录音状态按 `准备 → 录音中 → 待提交 → 验收中 → 已验收` 推进。当前步骤的语音质量提示落在该步骤内，重录只针对对应录音。所有任务完成后显示音域值和四个元音的完成状态，再执行原有的完成回调与用户上下文刷新。用户跳过标定时直接进入练习；主动重标定期间仍使用当前个人标定结果。

`useCalibration()` 管理会话、任务进度、录音 Blob、上传重试和提交结果；`CalibrationPanel.vue` 负责呈现。录音组件仍使用 `useRecorderStore()`，切换任务时释放上一步的预览地址和录音资源。API 客户端、生成类型与页面状态一并更新。

## 接口与会话

沿用 `GET /pitch-calibration` 获取个人标定状态，同时返回任务配置：四个元音的展示文字、各自目标次数、短文正文及 `textVersion`。标定录音仍使用现有音频上传接口，`purpose=calibration`。

新增持久化标定会话，建议接口如下：

| 接口 | 请求或返回的主要内容 |
| --- | --- |
| `POST /pitch-calibration/sessions` | 创建或返回当前用户进行中的会话；返回 `sessionId`、`textVersion`、任务进度。 |
| `GET /pitch-calibration/sessions/{sessionId}` | 返回已验收录音、待录任务、单条质量结果、最终计算状态。 |
| `POST /pitch-calibration/sessions/{sessionId}/takes` | 接收 `{audioId, kind: "vowel" | "pitch", vowel?: "i" | "u" | "a" | "ü"}`；分析单条录音，返回 `accepted`、`retry_take` 或 `additional_take_required` 及下一任务。 |
| `POST /pitch-calibration/sessions/{sessionId}/complete` | 在任务齐备后启动最终计算；返回会话状态，由 `GET` 查询完成结果。重复提交同一会话返回同一计算状态。 |

会话记录用户、配置版本、短文正文与逐字拼音、创建时间、状态、任务进度和最终快照 ID；单条记录保存 `audioId`、所属元音或短文、序号、验收结果及测量摘要。会话创建时固定短文版本。服务端按用户身份校验会话及音频归属、录音用途和任务类型。一条有效录音只归属一个任务。替换录音时标记前条为已替换，计算只读取当前有效录音。

最终计算经现有后台执行器运行。计算成功时，在同一数据库事务中写入个人标定值、不可变快照和会话完成状态，再刷新前端用户上下文。会话保留进度以支持刷新恢复；处理中断后同一会话可重新发起计算。已替换、完成或长期停留的会话录音按项目的私有音频清理机制处理。

按多条录音流程设置上传与标定接口限流：一次会话通常有九条录音，补录时数量增加；会话创建、单条验收和最终计算分别使用与其调用频率相符的配额。

## 声学计算与验收

### 单条元音录音

录音质量沿用现有音量、噪声、削波检查，并针对短元音录音设置独立时长阈值。短元音质检依据有声区间和共振峰可测性设置频带判定；短文使用语流录音的质量参数。根据能量与可靠基频定位连续有声段，取其中 30%–70% 作为稳态区。每条录音计算该区间的 `F1 / F2 / F3` 中位数、帧间波动和可用帧数，并将结果与元音标签关联。元音标签由当前任务确定，计算直接使用独立录音的有声区间。

每个元音取得两条有效录音后，立即使用同一暂定 Burg 上限比较稳态共振峰。初始复核阈值建议为两条录音的 `F1` 差异超过较大值的 15%，或 `F2` 差异超过较大值的 10% 时采集第三条；具体阈值使用真实用户标定录音校准。第三条加入后，按 `F1 / F2` 相对差异选取满足阈值且距离最近的两条参与锚点计算；三条分布仍明显分散时，界面提示重录该元音。不同录音在汇总时等权，使每条录音贡献相同。

将四个元音的有效稳态轨迹共同用于 Praat Burg 共振峰上限标定：候选范围 4500–6300 Hz，步长 100 Hz，窗长 25 ms、帧移 5 ms、50 Hz 预加重。选择轨迹平稳且四元音拓扑分离合理的上限。每个锚点输出跨录音的 `F1 / F2 / F3` 均值与标准差；`overall` 从四个锚点的 `F1 / F2` 中心计算，供现有归一化和 `P02` 绘图读取。计算结果记录每个锚点的样本数及所选上限。

### 音域短文录音

短文录音沿用现有语音质量检查、基频清洗、标定文本拼音与评分服务音节时间戳。评分服务为短文显式指定 `read_chapter` 题型，普通关卡继续使用各自题型。使用朗读区间内的可靠基频帧，按项目现有 `robust_pitch_range` 规则计算 `fLo / fHi`：可靠基频的第 3 与第 97 百分位向外扩展 6%。保留基频分布中位数、有效帧数和所用文本版本作为标定摘要。短文的语音质量或可靠基频不足时，返回短文这一步的重录提示；四个元音的有效录音继续保留在会话中。

元音空间和音域分别验收，最终一次提交形成同一份个人标定结果。

## 实施范围

- 前端：`src/features/calibration.ts`、`src/features/assessment/components/CalibrationPanel.vue`、`src/api/endpoints/detection.ts`、生成的 OpenAPI 类型；按任务设置 `src/stores/recorder.ts` 的录音上限。
- 后端接口：`backend/app/api/routes_audio.py`、`backend/app/api/schemas.py`；新增会话与单条录音状态的数据模型和迁移。
- 后端计算：`backend/app/scoring/usecases.py`、`backend/app/scoring/provider.py`、`backend/app/scoring/provider_xfyun.py`、`backend/app/acoustics/pronunciation_figures/vowel_space.py`；复用 `f0_pipeline`、44.1 kHz 转码与个人标定快照。
- 配置与消费：`backend/app/content/usecases.py` 的短文校验、`backend/app/detection/usecases.py` 的快照读取，以及 API 契约生成。后台参考发音人登记使用独立配置与计算入口。

## 验收条件

1. 四个元音各两条有效录音与一条短文录音可独立录制、试听、重录和提交；分散的元音样本触发第三条。
2. 刷新页面后恢复当前会话与已验收录音；某一步重录时其余步骤的进度保持。
3. 完成后个人记录与快照同时含音域、四个元音锚点和 `speaker_max_formant`；后续评测读取该快照并绘制 `P02` 元音空间。
4. 首次标定、主动重标定、跳过标定、质量重录、上传重试和重复完成请求均有对应的前后端测试。
5. 使用真实录音核对 `i/u/a/ü` 的空间拓扑、重复录音一致性及短文音域；核对 44.1 kHz 音频、API 返回和移动端标定界面。
