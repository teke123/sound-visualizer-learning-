# 一、sound-visualizer-learning- 的 F0 实现：前端“实时轨” + 后端“权威轨”双轨架构

核心设计：**录音时前端本地算 F0 只做即时反馈，不持久；上传后后端用 Praat 重算一遍，作为评分和结果曲线的唯一权威来源**。两条轨互不干扰，前端轨迹从不参与打分。

## 1. 前端（实时计算与展示）

**算法是 `pitchy` 库的 McLeod Pitch Method（NSDF 归一化平方差函数法）**，全部逻辑集中在 [realtimeAcoustics.ts](D:\桌面\项目实践声音\sound-visualizer-learning-\src\utils\realtimeAcoustics.ts)：

- **采集链**（[recorder.ts](D:\桌面\项目实践声音\sound-visualizer-learning-\src\stores\recorder.ts:95)）：`getUserMedia` 显式关闭回声消除/降噪/AGC（防止浏览器把底噪放大成假 F0），接 `AnalyserNode`，`fftSize=2048`（约 43ms，保证 65Hz 男低音窗内有 ≥2 个基音周期）。
- **逐帧流水线**（`RealtimePitchTracker.push()`，realtimeAcoustics.ts:111-188）：RMS 静音门限 0.015 → `findPitch()` 得 pitch+clarity → 只有 **pitch∈[65,500]Hz 且 clarity≥0.85** 才算有声（清辅音 clarity 通常 0.2–0.6，天然被滤掉）→ **半音域 3 点中值滤波**（剃单帧八度跳变）→ **EMA 平滑 α=0.35**；无声/清音连续超 3 帧就清空平滑状态，防止把两个音节平滑连成一条线。
- **清音段不浪费**：判为清音的帧计算能量加权谱重心，>5000Hz 提示“接近平舌”、否则“接近翘舌”（声母关教学用）。
- **展示**（[RealtimeAcousticCanvas.vue](D:\桌面\项目实践声音\sound-visualizer-learning-\src\components\RealtimeAcousticCanvas.vue)）：Canvas 2D + rAF（分析按 15ms 节流）。纵轴是**对数半音**（`12·log2(hz/55)`）；按关卡拼音画**五度目标引导带**（三声 `2→1→4` 折线，1 度=3 半音，挂靠当前窗口中心）；**无声帧抬笔留白，绝不补线**；纵轴窗口初始 85–320Hz，本人有声满 0.5 秒后自适应收缩到“个人均值 ±8 半音”。停止后整段定格，试听时画回放游标。

## 2. 后端（权威计算与归一化）

全部在 [analysis.py](D:\桌面\项目实践声音\sound-visualizer-learning-\backend\app\acoustics\analysis.py)：

- **预处理**：任意浏览器格式先 ffmpeg 统一转码 16kHz 单声道 PCM（`transcode.py`），PCM 哈希做内容幂等。
- **提取**（`extract_f0()`，analysis.py:163-242）：**Praat `To Pitch (ac)` 自相关法，经 parselmouth 调用**，10ms 帧移，搜索窗 65–420Hz，octave_jump_cost 0.35 等参数显式指定。后处理三件事：① 窗外值置 NaN；② **剔除前后皆无声的孤立单帧伪有声点**；③ 连续有声段合并（间隙 ≤80ms 算同段）。同时统计**八度跳变密度**（相邻有声帧 |log2 比值|>0.8 的占比）并给出**可靠性判定**（有声帧 ≥12、有声占比 ≥0.15、跳变密度 ≤0.12 才算 reliable）——不可靠时结果页直接不画曲线，不用可疑数据。
- **F0 通过 `GET /api/audio/{id}/f0` 暴露**，schema 是 `F0Frame{t, hz?}`——**无声帧不带 `hz` 键**（Praat NaN 语义），按 `(audio_id, kind, algorithm_version)` 缓存，算法一升级旧缓存自动失效。
- **音域与归一化**（对接评分）：
  - `robust_pitch_range()`：标定录音的对数域 **P3–P97 分位再外扩 6%** 作为个人音域（抗离群，注释明确写了“防喉化/嘎裂把范围撑爆”）；
  - `to_t_values()`：**对数域五度 T 值** `T = (ln f − ln lo)/(ln hi − ln lo) × 5`，裁剪到 [0,5]——和 citationtone_hub 的 robust FOR 同源；
  - `adaptive_f0_range()`：未标定用户跳过时，用本次录音 P5–P95 自适应；单字平调起伏不足时以中位数锚定下探 7 半音/上浮 4 半音构造音域。
- **结果曲线**（scoring/rules.py:122）：按讯飞返回的**音节时间戳**切 F0 段 → 剔首尾各 1 帧 → scipy 3 点中值滤波 → T 值换算 → 时间归一化 [0,1]，与关卡预存的“标准曲线”（参考发音人同套算法产出）逐音节配对。注意：**讯飞 ISE 只给音节级声调判分和调号，不给 F0 曲线**；F0 数值完全本地算。
- **展示**：结果页 [ToneCurveChart.vue](D:\桌面\项目实践声音\sound-visualizer-learning-\src\renderers\ToneCurveChart.vue)（echarts）画“我的曲线（蓝实线）vs 标准曲线（紫虚线）”，**纵轴就是 T 值 0–5**，段间 null 断开、markLine 标音节字。另外从 T 值曲线提取现象标签（二声起点偏高、三声偏平、四声降幅不足等 13 种）。

**一个重要发现**：后端 `backend/app/acoustics/tone_py/` 里**已经内置了 citationtone_hub（R 包 shinytone）的 Python 移植版 tone_py**（含 normalise_f0、chao 五度转换、inspect 检测等），版本号 `tp0.1.0` 都写进了算法版本串——**但 grep 全后端没有任何实际 import，纯闲置**。根目录 `D:\桌面\项目实践声音\tone_py\` 是它的源仓库，`shinytone_f0_extract.praat` 和 `extracted_f0.csv` 是配套 Praat 脚本及其产物，同样未被仓库引用。也就是说“借鉴 Shinytone”这件事在代码层面已完成了采购，只差接线。

# 二、citationtone_hub（Shinytone）是怎么做的

它是 R/Shiny 学术工具（Chenzi Xu & Cong Zhang，方法论 backing 是 Xu & Zhang 2024 JASA 综述），面向**方言田野语料的引证调研究**，和 sound-visualizer 的定位差异决定了它的设计哲学：**它不做任何自动“修数”，一切自动检测只产生标记，最终裁决靠人眼+人耳**；而 sound-visualizer 是面向学生的自动评分产品。

两条独立链：**F0 Processing**（wav → 提取 → 人工校正 → 导出 CSV）和 **F0 Analysis**（CSV → 归一化 → 检查 → 聚类/建模 → Chao 调值），中间靠“下载再上传”的检查点衔接。

- **提取三来源**（R/ 和 inst/app/ui/fp_extraction_ui.R）：① `wrassp::ksvF0`（默认 75–600Hz、10ms 帧移，`f0==0` 统一转 NA，同时算短时 RMS 强度）；② 解析 Praat 文本 `.Pitch`/`.PitchTier`——**保留每帧全部候选频率+置信度**（这是校正页“点一下候选就改值”的数据基础）；③ 直传 f0 CSV。另有内嵌的离线 Praat 批处理脚本（`shinytone_f0_extract.praat`），推荐 **filtered ac 法、50–800Hz 宽域**——宽域+滤波法正是它对抗八度错误的第一道防线。
- **归一化**（R/normalise.R:115）：`normalise_f0()` 先估说话人中心——**两级加权平均**（先算每调均值、再对调均值平均，防止某调录得多就把中心拉偏）——再换算 `f0_st = 12·log2(f0/speaker_mean)`（半音）或 z-score。
- **找坏数据**（R/inspect.R）：三层检测器（详见第四节）。
- **人工校正**（fp_correction_ui.R，3744 行）：plotly 三层图（波形+F0 点线+TextGrid 标注条），点大小编码强度、颜色编码旗标/编辑状态；编辑动作 ÷2/×2/删除/中值平滑/线性-抛物线-样条插值/手填 Hz/点选 Praat top-3 候选；每 token 独立 50 步撤销栈、完整编辑日志、非破坏性整条弃用（导出带 `token_dropped` 标记，数据永不删）；还有 **f0 声化试听**（`sonify_f0()` 相位积累合成滑音，编辑后 A/B 对比）和**波形上叠加声门脉冲**（肉眼数周期核验 F0）。
- **建模**：Polynomials（逐 token 勒让德正交多项式）、GCA（lme4 生长曲线）、GAMM（mgcv bam + **AR1 自相关校正**：先拟合估 lag-1 rho 再带校正重拟合——F0 帧密集采样残差强自相关，不校正值会偏乐观）。群体预测曲线流入 Summarise 页转调值。
- **聚类**（调类发现）：每 token 重采样 20 点，特征可选原始点/勒让德系数/DCT/一阶差分，定 k 用 elbow+silhouette+gap+**MDL 信息代价**+GMM-BIC 四路并报。

# 三、你专门问的四个问题

## 1. 五度标调怎么实现（`R/chao.R`）

两步走：**先平均轮廓，再换算取整**。

**第一步 `compute_mean_contour()`**：每 token 时间归一到 [0,1]，分 50 箱，按（调类×时间箱）求 F0 均值，得到每调一条代表性轮廓。

**第二步 `contour_to_chao()` 同时算三种 FOR（Fraction of Range）换算**，供并排对比：

| 方法 | 公式 | 音域取法 | 取整 |
|---|---|---|---|
| Reference-line [1,5] | 线性缩放到 [1,5] | 全语料 min–max | 四舍五入 |
| Interval (0,5] | 线性缩放到 (0,5] 分 5 等宽区间 | 全语料 min–max | 向上取整 |
| **Robust (0,5]（推荐）** | `(log f − log lower)/(log upper − log lower) × 5`，clamp 后向上取整 | **不用全体极值**：取最高调各 token 峰值的 μ+σ 作上限、最低调各 token 谷值的 μ−σ 作下限（对数尺度，Zhu 1999） | 向上取整 |

**取点规则**：调值首末位取归一化时间 0/1 处（插值）；仅在 10%–90% 内部找极值，且内部极值须比两端都高出/低出 **0.5 个 Chao 单位**才产生第三位数字（214 这种降升调）；缩放值落在整数边界 ±0.1（可调）内算“模糊值”标红，提醒该位数字取决于声调对立、有歧义。退化情形（整调是平线）参考线法记 3、区间法记 2.5。

这套东西 sound-visualizer 已经采纳了一半：`to_t_values()` 就是同一族对数 FOR 公式，但**只有一种换算、没有取整成调值数字、没有端点/转折点取点规则**。如果你们想在结果页直接给学生输出“你的发音约 24，目标是 214”，`chao.R:290-450` 可以几乎照抄（vendored tone_py 里就有现成 Python 版）。

## 2. 说话人音域怎么取得

两边思路完全不同，恰好互补：

- **citationtone_hub：不标定，从语料本身统计**。① 归一化用“说话人中心”（两级加权平均的半音/z-score）；② 五度换算用 robust μ±σ 峰谷法（见上表）——上限来自**最高调的峰值**、下限来自**最低调的谷值**，本质是“让数据里真实的调域极差定义五度”，没有单独的音域采集任务。
- **sound-visualizer：主动标定**。读六单韵母的标定录音 → `robust_pitch_range`（P3–P97+6%）→ 存为用户级 `pitch_range`，检测受理时**冻结快照**（保证曲线口径不随日后重标定漂移）→ 未标定用户用默认成人音域，并用单次录音 P5–P95 原地升级为“自适应音域”→ 还有滚动重算（标定基线+最近 20 条录音）。

可借鉴点：robust FOR 的**峰谷 μ±σ**思路比纯分位数更能对抗离群（一次跑调撑不爆范围）；而“受理时冻结快照”的口径管理是 Shinytone 没有的、你们已经做得更好的地方。

## 3. 音高跳跃、嘎裂、气泡音怎么处理

Shinytone 的总原则（操作手册 4.6 节 + 波形阅读指南）：**区分“Case 1 真提取错误（该修）”和“Case 2 信号本身特殊（是分析决策，不许逐条手工清洗）”**——句尾 creak、气声起音、双周期嗓音都属于 Case 2，必须**事先定一条全语料统一规则**（如“只分析 modal 声段”或“统一强度阈值去帧”），一视同仁并记录在案。

具体机制分四层：

1. **提取层预防**：Praat 脚本推荐 filtered ac + **50–800Hz 宽域**（宽范围下通常无需按人调校，减少八度错误）；手册明确“已知发音人 creaky 偏多可调低下限”——**气泡音/嘎裂常低到 50Hz 以下，下限过高会直接测丢或误报半频**。⚠️ 这一点对你们直接适用：后端目前 65–420Hz 的下限会把一部分嘎裂尾判成无声或半个八度。
2. **自动检测层**（inspect.R，只标记不改数）：
   - **八度跳变**：Hz 比 <0.49 或 >1.99 直接判 octave；相邻帧半音差按每 10ms 归一后**升 >1.263 / 降 >1.714 半音**判速率跳变（阈值来自 Sundberg 1973 人声基频生理变化率上限，物理上不可能超）；改进点：**旗标打在离 token 中位数更远的那帧**（首尾伪影也能标对侧）；再向两侧做 **carryover 残留扩展**（错误八度往往连着好几帧）。
   - **整条错八度**：token 的 max/min 在说话人内做 z-score，只标外侧越界（min too low 正是 creak 拉低或半频的特征）。
   - **嘎裂/气泡音的间接信号**：`flag_low_intensity`——帧强度低于本 token 峰值 15dB 即标“低强度”（起振、清化、吱嘎尾都又轻又不可靠），只提醒不判死。
3. **人工裁决层**（校正页）：波形+F0 同屏听看改；÷2/×2 一键修八度；点选 Praat **top-3 候选**改值（保留候选的价值在这里兑现）；波形上叠**声门脉冲**肉眼数周期是最终核验手段；大语料（≥1000 token 且标记率 ≤15%）走“批量弃用→抽查恢复”的分诊通道而不是逐个修。
4. **统计层兜底**：归一化用中位数/MAD 等稳健统计，几帧跳变拉不偏 speaker 均值；GAMM 的说话人随机效应可吸收未清洗的嗓音变异。

对照你们的现状：sound-visualizer 对跳跃只有“中值滤波（剃单帧）+ jump_density 可靠性降级（不画图）”，**没有逐帧标记、没有 carryover、没有候选机制、没有人工复核入口**；对嘎裂/气泡音没有任何专门处理（除了 robust 音域抗污染）。短期最划算的借鉴就是 inspect 三层检测——vendored tone_py 里现成。

## 4. 静音段怎么处理

Shinytone 的约定贯穿全部代码：**“无声”= f0 是 NA 或 0**（提取器常把无声帧记 0）。三条铁律：

1. **绝不跨过无声段插值**：等距重采样时近帧有声+远帧有声才做加权平均，任一侧无声就取有声侧实测值，两侧都无声留 NA——否则一段清音会被悄悄填平，“发声中断”的证据就没了（逐条对齐 Praat `Get value at time` 行为）。
2. **孤立帧不可信，连续性才是证据**：`trim_to_voiced` 取浊音区时首尾必须落在**连续 ≥2 帧有声**的游程上（防头尾静音里的单个假值把区间拉宽）；中段缺口原样保留，时长计算不因缺口缩短。
3. **中断要显式标记而不是藏起来**：`flag_f0_gaps` 给每 token 记 `n_missing`（缺帧数）和 `has_gap`（是否中段断浊，首尾静音不算），导出时默认**保留空行**（绘图显示断口），并提醒这必须在原始帧网格上做——重采样会把短缺口插值填掉、把问题藏起来。

（根目录那份 `extracted_f0.csv` 的列结构里就有 `n_missing`/`has_gap`，就是这条管线的产物。）

对照你们：前端已同款实现（RMS 门限判静音、3 帧断链清平滑状态、绘制抬笔留白），后端“unvoiced 帧不带 hz 键 + 孤立帧剔除 + ≤80ms 间隙合并”也基本对齐；**缺的是 has_gap/n_missing 这类显式中断标记**，以及“不跨段插值”你们暂时没有等价场景（曲线只切段内归一化，风险不大）。

## 1. 前端 F0 计算（实时轨）

**算法：pitchy 库（McLeod Pitch Method，NSDF）**，文件 `D:\桌面\项目实践声音\sound-visualizer-learning-\src\utils\realtimeAcoustics.ts`

- 依赖：`package.json:26` `"pitchy": "^4.1.0"`；`realtimeAcoustics.ts:11` `import { PitchDetector } from 'pitchy'`
- 头注释（第 5–9 行）明确方法论："基频用 pitchy（McLeod Pitch Method，NSDF）提取，输出 pitch + clarity…平滑在半音域做「3 点中值滤波 + 一阶指数平滑（EMA）」"

关键参数（第 13–23 行）：
```ts
export const ANALYSIS_FFT_SIZE = 2048      // 帧长 2048 点（≈43ms @48k）
export const F0_MIN_HZ = 65                // 人声搜索窗 65–500 Hz
export const F0_MAX_HZ = 500
export const CLARITY_GATE = 0.85           // 清浊门限（清辅音 clarity 通常 0.2–0.6）
export const SILENCE_RMS_GATE = 0.015
export const CLIPPING_PEAK = 0.95
```

核心类 `RealtimePitchTracker`（第 111–188 行），`push()` 每帧流程：
1. 手工算 RMS/peak/削波标志；
2. `rms >= SILENCE_RMS_GATE` 才调 `this.detector.findPitch(input, this.sampleRate)`（第 153 行）；
3. 有声判定：`pitch ∈ [65,500]Hz 且 clarity ≥ 0.85`（第 155 行）；
4. **平滑链**（第 158–164 行）：Hz→半音 → 3 点滑窗中值滤波（剃单帧八度跳变）→ EMA（`emaAlpha=0.35`，构造器第 123 行）→ 半音→Hz 输出；
5. 无声/清音持续 >3 帧即清空中值窗与 EMA 状态（`breakStreak`，第 180–187 行），防止跨音节连线平滑；
6. 清音帧附加计算能量加权**谱重心** `spectralCentroidHz()`（第 230–243 行，字节 dB 还原线性幅度，地板 `CENTROID_FLOOR_BYTE=20`），用于区分平舌/翘舌摩擦（>5000Hz 提示）。

**Web Audio 采集链**：`src/stores/recorder.ts`
- `getUserMedia` 显式关闭 `echoCancellation/noiseSuppression/autoGainControl`（第 95–101 行）以保真音高；
- `AudioContext` + `createMediaStreamSource` + `AnalyserNode`，`analyser.fftSize = ANALYSIS_FFT_SIZE`（2048，第 105–111 行，注释说明 65Hz 男低声需 ≥2 个基音周期，1024 不够）；
- 采样率取自 `analyser.context.sampleRate`（由 RealtimeAcousticCanvas 传入 tracker 构造器）。

**驱动循环**：`src/components/RealtimeAcousticCanvas.vue:100-137`，rAF 内每 ≥15ms（约 60fps）执行一次：`analyser.getFloatTimeDomainData(timeBuf)` + `getByteFrequencyData(freqBuf)` → `tracker.push()`。

**自适应纵轴** `AdaptivePitchWindow`（realtimeAcoustics.ts:198-218）：默认 85–320Hz；有声累计满 0.5 秒后向"本人平均半音 ±8 半音"平滑收缩（每次 10%）。

**单测**：`src/utils/__tests__/realtimeAcoustics.spec.ts` 覆盖半音互逆、220Hz 正弦收敛、静音判 silence、白噪声判 unvoicedNoise、中值滤波剃八度跳变、断流清状态。

## 2. 后端 F0 计算（权威轨）

**算法：Praat `To Pitch (ac)` 自相关法（parselmouth）**，文件 `backend/app/acoustics/analysis.py`

- `extract_f0()`（第 163–242 行），参数（第 173–185 行）：
```python
parselmouth.praat.call(snd, "To Pitch (ac)",
    F0_HOP_MS/1000.0,  # 10ms 帧移（F0_HOP_MS=10.0，第 26 行）
    F0_MIN_HZ,         # 65Hz（第 24 行）
    15,                # candidates
    "no", 0.05,        # silence_threshold —— 抑制送气段伪有声
    0.52,              # voicing_threshold
    0.01, 0.35, 0.14,  # octave_cost / octave_jump_cost / voiced_unvoiced_cost
    F0_MAX_HZ)         # 420Hz
```
- 后处理：窗外值置 NaN（第 188 行）；**剔除前后皆 unvoiced 的孤立单帧伪有声点**（第 191–197 行）；连续有声段合并（间隙 ≤80ms，第 202–217 行）；**八度跳变密度**统计（相邻有声帧 |log2 比值|>0.8，第 219–226 行）；可靠性 `n_voiced≥12 且 voiced_ratio≥0.15 且 jump_density≤0.12`（第 236 行）。
- 上传音频先经 ffmpeg 转码为 **16kHz 单声道 PCM**（`transcode.py:15` `SAMPLE_RATE = 16000`）。
- 依赖只有 `praat-parselmouth>=0.4.3`（requirements.txt:12），**无 librosa/crepe/opensmile**。
- `ALGORITHM_VERSION = "acx-1.1.0+tp0.1.0+pm0.4.7"`（config.py:98），进入 F0 缓存键。

**F0 相关端点**（`backend/app/api/routes_audio.py`，FastAPI，前缀 `/api`）：
- `GET /audio/{audio_id}/f0`（第 69–76 行）→ `acoustics_uc.get_f0()`（`usecases.py:118-129`，FeatureCacheRow 按 algorithmVersion 缓存），响应含 `frames[{t,hz?}], voicedRanges, voicedRatio, hopMs, algorithmVersion`；
- `GET /audio/{audio_id}/formants`、`formants.png`、`spectrogram.png`（共振峰与频谱图，同文件第 79–111 行）；
- `GET/POST /pitch-calibration`（第 116–176 行）→ `scoring_uc.compute_calibration`。

**讯飞(xfyun)不含 F0 曲线**：`backend/app/scoring/provider_xfyun.py` 是流式版语音评测 WebSocket 适配器（open-ise），返回的是按音节的**声调判分**（`tone_score`、`tone_ok`、`tone_value` 调号、`mono_tone`，见第 246/322/334 行），只用于音节时间戳切分（`syl.t0/t1`）和调号识别；F0 数值本身完全由本地 parselmouth 计算。

## 3. F0 数据处理（后端归一化链）

均在 `backend/app/acoustics/analysis.py` 与 `backend/app/scoring/`：

- **标定音域** `robust_pitch_range()`（analysis.py:245-256）：对数域分位数 **P3–P97 外扩 6%**（覆盖五度全调域、抗喉化离群），帧数 <20 或带宽 <5% 判无效。
- **T 值换算** `to_t_values()`（analysis.py:259-266）：对数域 FOR，`(log f − log lo)/(log hi − log lo) × 5`，**裁剪到 [0,5]**（非 D 值、非半音绝对标度）。这是本项目归一化的核心（声调五度制）。
- **自适应音域** `adaptive_f0_range()`（analysis.py:433-449）：未标定用户跳过路径——录音起伏充分（hi>lo×1.18）取 P5–P95 外扩 8%；单字平调则以中位数 F0 锚定，下探 7 半音/上浮 4 半音构造个人音域，替代默认 `DEFAULT_ADULT_F0_RANGE=(95,260)`（config.py:101）。检测管线在受理时原地升级快照（detection/usecases.py:258-263）。
- **结果曲线** `_t_curve_in_segment()`（scoring/rules.py:122-142）：按讯飞音节时间戳切 F0 段 → 剔首尾各 1 帧 → **scipy 3 点中值滤波**（第 130–132 行）→ T 值换算 → 时间归一化到 [0,1]。
- **标准（参考）曲线**：`content/usecases.py:465-524` 对参考发音人示范音频做同一套提取+中值滤波+`to_t_values`（第 499 行），存为关卡 `standardCurve`。
- **标定流程** `scoring/usecases.py:84-147 calibrate_path`：信号质检 → `extract_f0` → `robust_pitch_range` 得 fLo/fHi + 六单韵母元音空间；`compute_calibration`（第 150–197 行）写 `PitchRangeRow`+快照，标定音频算完即删。另有滚动重算（第 210 行起，基线+最近 N 条存档录音 F0 统计）。
- **现象提取** `curve_phenomena()`（rules.py:176-219）：从 T 值曲线按调型规则给出诊断（如二声起点 v20>3.2 偏高、升幅 <1.2 度不足、一声尾滑 >1.2 度等）。

## 2. 五度标调（Chao tone numerals）

核心在 `R/chao.R`，三个导出函数：`compute_mean_contour()`、`classify_contour()`、`contour_to_chao()`。

**`compute_mean_contour(data, token, f0, time, tone, n_bins = 50, time_normalised = "auto")`**（`chao.R:71-103`）：每 token 时间归一到 [0,1]（`resolve_time_norm`），`round(t*(n_bins-1))/(n_bins-1)` 分箱，按 (tone, time_bin) 求 f0 均值 → `tone/time/f0_predicted` 长表。

**`contour_to_chao(contour_data, tone_col, time_col, f0_col, threshold = 0.5, raw_data, ...)`**（`chao.R:290-450`）一次算出三种 FOR（Fraction of Range）归一化：
- **Reference-line（[1,5] 参考线）**（330 行）：`f0' = (f0 - f0_min)/(f0_max - f0_min) * 4 + 1`，**取整 round**（410 行）。
- **Interval（(0,5] 等宽区间）**（331 行）：`f0' = (f0 - f0_min)/(f0_max - f0_min) * 5`，**向上取整 ceiling**（411 行）。
- **Robust FOR（对数半音域）**（`chao.R:337-364`）：范围不用全体 min/max，而是——按调均值找最高调与最低调；最高调各 token 的 f0 峰值取 μ_max、σ_max，最低调各 token 的 f0 谷值取 μ_min、σ_min；`upper = μ_max + σ_max`，`lower = max(μ_min − σ_min, 1)`，然后
  `chao = (log f0 − log lower) / (log upper − log lower) * 5`，clamp [0,5] 后 ceiling（363-364、412-413 行）。即 Zhu (1999) 式对数 T 值公式（分母是 log 半音程、乘 5 而非 4）。参数以属性 `robust_stats` 附在返回值上（439-448）。

**调值从曲线取点规则**（`chao.R:374-413`）：对每调构建 `approxfun(time, chao值, rule=2)`，端点取 `interp(0)` 与 `interp(1)`；再在 `seq(0,1,length.out=200)` 细网格上、仅内部区间 `[20:180]` 找 interior min/max（390-391）；若内部极小值比两端都低 `threshold`（默认 0.5 个 Chao 单位）判为 dip，内部极大值同理判为 peak（395-398）→ 三位数取 `c(0, 转折点, 1)`，否则两位数 `c(0,1)`。`n_digits` 列记录位数。

**`classify_contour(chao_str)`**（`chao.R:153-177`）：全同数字→low/mid/high level 等 5 档；内部极小→"dipping"，内部极大→"peaking"；否则首尾比较→rising/falling/level。

Shiny 端 Summarise tab（`inst/app/ui/summarise_ui.R`，约 198-300 行）直接调 `compute_mean_contour()` + `contour_to_chao()`，并把整数边界 ±t 的模糊值标红（59-73 行的说明文字）。**注意 T 值公式在本项目是 log 域 0-5 制（robust），另有线性域 [1,5]/(0,5] 两个变体**。

## 3. 说话人音域（pitch range）

**没有发音人单独音域标定（无朗读音域任务），也不用 5%/95% 百分位**；有两处"说话人参照"实现：

1. **`normalise_f0(data, f0, speaker, tone, method = c("semitone","zscore"), mean_method = c("weighted","simple"))`**，`R/normalise.R:115-170`：
   - 先算每说话人 `speaker_mean`：`weighted`（默认）= 先按 (speaker,tone) 求均值、再对 per-tone 均值取平均，各调等权（144-151 行）；`simple` = 全体算术均值。
   - `semitone`：`ST = 12 * log2(f0 / speaker_mean)`（166 行），输出列 `f0_st`。
   - `zscore`：`Z = (f0 - speaker_mean) / sd(speaker_f0)`（158-163 行），输出 `f0_zscore`。
2. **Robust FOR 的音域**（见第 2 节）：μ±σ 峰谷法，最高调峰均值+1σ 作上限、最低调谷均值−1σ 作下限——这是 Chao 转换时的"音域"。

辅助：`flag_level_outliers()`（`R/inspect.R:240-303`）用每 token 中位 f0 的半音值 `12*log2(median)` 在 speaker×tone 组内做稳健统计（见下节）。

## 6. 建模与可视化

「三种建模」= ui.R 的 **Model: Polynomials / Model: GCA / Model: GAMM** 三个子 tab（`ui.R:1833-1863`），另有 Cluster（无监督调类发现）与 Summarise（Chao）：

- **`fit_polynomial(data, f0, token, time, speaker, tone, degree = 2, time_normalised)`**，`R/polynomial.R:104-167`：每 token OLS 拟合 **Legendre 正交多项式**（时间→[0,1]→`2t-1`→[-1,1]），基由 Bonnet 递推构造（`legendre_basis()` 174-189），`stats::lm.fit`；输出 `c0`(均值)/`c1`(斜率)/`c2`(曲率)/`c3`(S 形)。degree 1-3。
- **`fit_gca(...)`**，`R/gca.R`：`lme4::lmer()` + `stats::poly()` 正交时间多项式 `ot1..otK × tone`，常规 by-speaker 随机截距+斜率、by-item 截距；REML；S3 类 `shinytone_gca`，`predict_gca()` 复用 poly 系数。
- **`fit_gamm(...)`**，`R/gamm.R:164-356`：`mgcv::bam(..., discrete = TRUE)`；`smooth_type = "separate"`（默认）→ `s(time, by = tone, k, bs = "tp")`，`"difference"` → 参考 smooth + ordered 因子差 smooth（Sóskuthy 2021 策略）；随机平滑选项 `random_smooth = none/speaker/speaker_tone/speaker_by_tone/ref_diff`（`bs="fs", m=1`），随机截距 `s(x, bs="re")`，可选 `s(duration)` 时长协变量；**AR1 修正默认开**：先拟合、用组内（per-token）lag-1 残差自相关估 `rho`（`grouped_acf`，313-326），再带 `rho` + `AR.start = !duplicated(token)`（247 行）重拟合（327-335）。`predict_gamm(n=200)` 排除随机项给群体均值曲线+SE；`diagnose_gamm()`（671 行起）输出 k 检查、残差四联图、per-token 残差 ACF、`mgcv::concurvity()`。
- **聚类**（`R/cluster.R`，目的=估计未知方言调类数）：`cluster_features()`（119-201）每 token 重采样 n_points=20，特征 `points/legendre/dct/derivative`（一阶差分，按"变化率"聚类），`register = level/shape`；`choose_k_f0()`（242-310）= elbow + silhouette + gap(1-SE) + **MDL 信息代价**（`.mdl_cost()` 68-89，Kaland & Ellison 2023，模型代价+划分代价+残差代价，可调 bending）+ GMM-BIC（mclust 对角模型 EII/VII/EEI/VVI）；`cluster_f0()`（371-412）kmeans/hclust(ward.D2)/GMM，簇按均值高度重编号；`cluster_agreement()`（423-441）自实现 ARI。
- **声音合成（无 PSOLA）**：`sonify_f0(f0_hz, fs=16000, dur=0.7, source = "tone"/"complex"/"vowel", vowel = a/i/u, intensity, dyn_range)`，`R/sonify.R:88-157`：相位积累 `phase = cumsum(2π·f0/fs)` 生成连续滑音；`vowel` 是 Klatt 式源-滤波（1/h 谐波源 + 三个二极点共振器级联，F1/F2/F3 表见 44-47 行）；intensity(dB) 包络 `10^((dB−max)/20)`。用于 Correction 试听、Cluster 原型回放（`cluster_ui.R:352-360`，pitch 可选 "faithful" 原 Hz）。
- **前端绘图**：Visualise tab = **ggplot2**（`visualise_ui.R:201-220`：`geom_line(aes(group=token)) + geom_point`，按 tone 着色、可按 speaker facet，landmark 对齐时画分段竖虚线；还生成可复制的 R 代码 388-405）；GAMM/GCA 预测图也是 ggplot2 + `geom_ribbon(±1.96*se)`（`gamm_ui.R:962-991`）；F0 Correction = **plotly** 交互三层图（见第 4 节）；`praatpicture` 只在 `server.R:90` 被 library() 但代码中无实际调用（预留依赖）。

### 一、 发现的 5 个致命代码缺陷（现状诊断）

在讲改进前，先指出我在源码中查到的 5 个直接破坏曲线质量和五度准确性的 bug：

1. **段内时间归一化“偷吃”了静音/嘎裂断口（严重失真）**
   在 [rules.py:126-141](backend/app/scoring/rules.py:126) 的 `_t_curve_in_segment()` 中：
   ```python
   mask = (ts >= seg[0]) & (ts <= seg[1]) & np.isfinite(hz)
   t_sel, hz_sel = ts[mask], hz[mask]
   ...
   span = t_sel[-1] - t_sel[0]
   {"t": (ti - t_sel[0]) / span, "v": v}
   ```
   这里先把 `NaN`（无声帧）过滤掉，再做 `medfilt`，最后生成连续点传给前端 ECharts，而 [ToneCurveChart.vue:88](src/renderers/ToneCurveChart.vue:88) 虽然写了 `connectNulls: false`，**但后端根本没传 `null`！**
   **后果**：如果用户发第三声 `214` 中间出现 150ms 的低压嘎裂（被判为 unvoiced `NaN`），或者发字中间断气，后端会把两侧有声帧直接拼在一起，ECharts 用一条平滑实线硬连过去，不仅掩盖了断音，还让转折点时间坐标严重错位。
2. **Praat 算法版本落后，且窗口锁死 `65–420Hz`**
   [analysis.py:174](backend/app/acoustics/analysis.py:174) 使用的是旧版 `To Pitch (ac)`，而非 Praat 6.4+ 专门为抑制八度跳变设计的 **`To Pitch (filtered ac)`**（先低通滤波再做自相关）。同时 `65Hz` 下限高于很多男声三声谷底/四声句尾的气泡音（常在 `45–60Hz`），`420Hz` 上限又会把部分女高音/儿童高音削顶。
3. **八度跳变“一刀切”拒画，而非自动修复**
   [analysis.py:236](backend/app/acoustics/analysis.py:236) 规定 `jump_density > 0.12` 就直接判 `reliable = False`，前端直接显示“本次没有可用的音高曲线”。实际上，声调练习中 80% 的跳变都是自相关在嘎裂段/气声段选错了倍频或半频候选（`×2` 或 `÷2`），完全可以在候选路径或后处理中平滑修复，而不是直接报错拒画。
4. **前端实时窗口与个人标定音域脱节**
   [realtimeAcoustics.ts:198](src/utils/realtimeAcoustics.ts:198) 的 `AdaptivePitchWindow` 每次录音都从 `85–320Hz` 重新收敛，且假定 `1 度 = 3 半音`（五度跨度固定 12 半音）。如果用户做过音域标定（或已有历史自适应音域），前端录音时根本没用上，导致**录音时看到的目标引导带和最终评分时的 T 值坐标系不一致**。
5. **`tone_py` 守着宝山未接线**
   `backend/app/acoustics/tone_py/` 已经完整移植了 `shinytone` 的 `inspect_f0`（Sundberg 生理极限跳变检测 + Carryover 扩展 + 低能量标记）、`resample_f0_equal`（绝不跨无声段插值）、`contour_to_chao`（五度数字转写与模糊边界检测），但一行都没被调用。

### 二、 核心改进方案（四大模块）

#### 模块 1：后端基频提取管线升级（更可靠、更鲁棒）

建议采用 **“Praat `filtered ac`（多候选 + 强度联合提取）为主，可选 `torchcrepe` / `parselmouth` 双引擎融合”** 的方案：

1. **切换为 `To Pitch (filtered ac)` 并放宽物理搜索窗**
   `parselmouth`（基于 Praat 6.4+）原生支持 `To Pitch (filtered ac)`。这是 `citationtone_hub` 首推的方法：
   - 搜索窗设为 **`50–600 Hz`**（覆盖低频气泡音到女高音）。
   - 同时提取 **短时强度 `To Intensity`** 并对齐到 10ms 帧网格。
2. **引入候选帧重选（Candidate Re-ranking）或生理速率约束 Viterbi**
   Praat 的 `Pitch` 对象每一帧都保存了最多 15 个 `(frequency, strength)` 候选。当前代码只无脑取了 `selected_array["frequency"]`（候选 1）。
   - **改进**：取出每帧 Top-3 候选。当相邻帧发生违背人类声带生理极限的跳变（引用 `tone_py/inspect.py` 中的 **Sundberg 法则：上升 > 1.263 半音/10ms，下降 > 1.714 半音/10ms**，或倍频比 `>1.99` / `<0.49`）时，检查该帧的第 2、第 3 候选是否落在当前音节中位数半音邻域内。如果在，**直接替换为正确的候选频率**，从根源上消除 `×2 / ÷2` 八度毛刺。
3. **（可选进阶）引入轻量级神经网络或 PYIN 兜底**
   - 如果环境允许 PyTorch，**`torchcrepe`（`tiny` 或 `small` 模型）** 或 **`RMVPE`** 在抗噪、抗送气干扰和声门激励退化上远强于传统自相关，且输出逐帧 `periodicity`（置信度）。
   - 如果保持纯 CPU 轻量依赖，可用 **`librosa.pyin`** 或 **Praat `filtered ac` + `tone_py.inspect`** 组合，延迟在 15ms 以内。

#### 模块 2：静音段、嘎裂（Creaky Voice / 气泡音）、跳跃的专项处理

这是声调教学软件最核心的痛点。不能把“嘎裂”简单当成“噪声”删掉（因为在普通话里，**第三声 `214` 的谷底和第四声 `51` 的末尾出现嘎裂/气泡音是极其自然且正确的生理现象**，甚至低音区的嘎裂恰恰证明学生三声压下去了！）。

1. **嘎裂 / 气泡音（Creaky Voice）识别与“低压带”保留机制**
   - **声学特征**：嘎裂时声带呈现不规则低频振动或双周期振动（Diplophonia / Subharmonics），表现为：**F0 骤降到个人音域底部或突然减半（半频 `÷2`）、自相关强度（clarity / periodicity）下降到 `0.35–0.55`、伴随帧强度（Intensity）低于本音节峰值 10–15dB，且紧邻正常浊音段内部或末尾**。
   - **改进策略（三步法）**：
     1. **双门限提取**：主浊音门限保持 `voicing_threshold = 0.50`；但在已有稳定浊音段的**音节中段（三声谷底）和音节尾段（四声收尾）**，开启“嘎裂拯救窗”：允许 `voicing_threshold` 降至 `0.32`、频率下探至 `45Hz`，但要求帧能量高于环境底噪 `+8dB` 且过零率（ZCR）< 0.18（排除清擦音 `s/sh/x`）。
     2. **半频折叠校正（Subharmonic Unfolding）**：若某帧被标记为 `creaky` 且其频率恰好约为前一稳定帧的 `1/2`（比值在 `[0.46, 0.54]`），说明出现了双周期气泡音（Period-doubling），将其乘以 2 或锚定在个人五度音域的 `1 度（T ∈ [0.5, 1.2]）` 地板上，而不是让它掉到 `T=0` 或断线。
     3. **单独标记 `quality: "modal" | "creaky" | "unvoiced"`**：在帧结构里返回嗓音质量标签，前端用**琥珀色虚线或点状散点**绘制嘎裂段，并给学生正向或精准提示（例如：“第三声低音区出现了自然的气泡音，低音压得很实”或“句尾气息不足产生喉音”）。

2. **音高跳跃（Octave Jumps）的四步清洗流水线（直接盘活 `tone_py/inspect.py`）**
   不再用粗暴的 3 点中值滤波了事（3 点中值滤波只能剃掉 10ms 的单帧毛刺，连续 2 帧跳变就完全失效）：
   - **Step 1**：运行 `tone_py.inspect.flag_pitch_jumps()`，利用 Sundberg 生理速率阈值识别跳变起止点，并执行 **双向 Carryover 扩展**（把连着 2–5 帧的错误八度平台整块抓出来）。
   - **Step 2**：对被标记为 `octave jump` 或 `carryover` 的连续帧块（长度 ≤ 60ms），先尝试用 Praat 次优候选或 `÷2 / ×2` 修正；若修正后与两侧斜率吻合，则采纳。
   - **Step 3**：若无法通过倍频修复，将该异常块置为 `NaN`，仅当缺口 `≤ 40ms`（4 帧）且两侧均为高置信度浊音时，在半音域做 **PCHIP（保形分段三次 Hermite 插值）**；若缺口 `> 40ms`，严格保持 `NaN` 断开。
   - **Step 4**：在半音域使用 **Savitzky-Golay 滤波（窗口 5 或 7 帧，二次多项式）** 替代简单中值滤波，既平滑微观抖动（Jitter），又完美保留三声拐点的曲率。

3. **静音段与清音段的铁律（对齐 `tone_py/resample.py`）**
   - **头尾修剪（`trim_to_voiced`）**：每个音节的声调测量区间，绝不能直接用讯飞 ISE 的音节起止时间 `(t0, t1)`（因为那包含了声母 `p/t/k/s/sh` 和句尾静音），必须裁剪到音节内**首个连续 ≥ 3 帧（30ms）有声帧**到**末个连续 ≥ 2 帧有声帧**之间（即韵母核心区 Rhyme/Toneme）。
   - **绝不跨静音插值**：重写 `_t_curve_in_segment()`，调用 `tone_py.resample.resample_f0_equal(n=21)` 的逻辑——在归一化时间轴 `0.00, 0.05, ..., 1.00` 的 21 个等距采样点上，**只要近邻帧是 unvoiced，该采样点就输出 `v: null`**，交给 ECharts 原生断开！同时输出 `hasGap: true` 标记发声中断。

#### 模块 3：个人音域获取与五度标音（Chao Tone Letters）重构

目前系统只输出连续曲线 `T ∈ [0, 5]`，没有真正给出赵元任五度标调的**离散调值数字（如 `55`、`35`、`214`、`51`）**，且个人音域容易受单字录音影响。建议如下：

1. **三层递进式“个人音域（Speaker Pitch Range）”模型**
   结合 `sound-visualizer` 的“快照机制”与 `citationtone_hub` 的“稳健峰谷统计（Zhu 1999）”：
   - **冷启动（第 1 次开口，无标定）**：改进现有的 `adaptive_f0_range()`。人类普通话四声的生理调域跨度通常在 **8–12 个半音（约 0.7–1 个八度）**。当用户只读了一个单字（比如阴平 `mā` 55，F0 几乎是平线 220Hz），若知道目标调号是 1 声（55），就不应该把 220Hz 当成音域中心（3.5 度），而应**根据目标调号反推音域基线**（若当前读的是 1 声且讯飞判定声调正确，中位数锚定在 `T=4.5` 附近，向下推算 10 半音作为 `f_lo`）。
   - **滚动稳健音域（Rolling Robust FOR，推荐核心方案）**：参照 `citationtone_hub` 的 `contour_to_chao(robust)` 思想——在数据库或本地维护用户最近 15–30 个有效音节的**高音峰值集合（来自 1 声、2 声尾、4 声头）**与**低音谷值集合（来自 3 声谷、4 声尾）**：
     $$\text{Upper (5度顶)} = \exp(\mu_{\ln(\text{peaks})} + 1.0 \cdot \sigma_{\ln(\text{peaks})})$$
     $$\text{Lower (1度底)} = \exp(\mu_{\ln(\text{valleys})} - 1.0 \cdot \sigma_{\ln(\text{valleys})})$$
     这种方法比单纯对所有帧取 `P3–P97` 科学得多——因为如果用户连续练了 10 个第一声（55），`P3–P97` 会把窄窄的高音区当成全部五度；而**分声调峰谷统计（Two-level weighted stats）**永远不会被单一调类带偏！
   - **主动标定任务升级**：当前的“六单韵母标定”主要服务于共振峰（元音空间），如果用来标定音域，都读第一声根本测不出音域下限！建议标定引导词改为**四声全覆盖短词（如“山明水秀 `shān míng shuǐ xiù`”或“妈麻马骂 `mā má mǎ mà`”）**，一次录音 3 秒即可精准锚定 5 度顶与 1 度底。

2. **五度标调自动转写算法（直接接入 `tone_py/chao.py`）**
   在结果页不仅画曲线，还直接为每个音节算出**“你的实际五度调值” vs “标准五度调值”**（例如：*目标 `214`，你读成了 `212`（尾音上扬不足）* 或 *目标 `51`，你读成了 `42`（起调偏低、降幅不够）*）：
   - **公式换算**：采用对数半音域映射到 `[1, 5]` 连续值：
     $$D(t) = 1 + 4 \times \text{clip}\left(\frac{\ln f_0(t) - \ln f_{\text{lo}}}{\ln f_{\text{hi}} - \ln f_{\text{lo}}}, 0, 1\right)$$
     （注：赵元任五度制数字是 `1, 2, 3, 4, 5`，用 `1 + 4 * ratio` 四舍五入比 `[0, 5]` 向上取整更贴合传统语音学直觉，也可同时保留 `tone_py` 的 Robust `(0, 5]` ceiling 模式）。
   - **拐点与端点提取规则（借用 `chao.py` + 边缘防抖）**：
     - 丢弃音节头尾各 `8%` 的协同发音过渡段（Consonant perturbation，如塞音除阻后的瞬态 F0 下冲）；
     - 起点取 `t = 0.08` 处，终点取 `t = 0.92` 处；
     - 在内部 `[0.15, 0.85]` 区间搜索极值：若内部极小值比起点和终点都低 **≥ 0.5 度**，输出 **3 位数字（凹调 Dipping，如 `214`）**；若内部极大值比两端都高 **≥ 0.5 度**，输出 **3 位数字（凸调 Peaking，如 `352`）**；
     - 若起点与终点差值 `< 0.4 度` 且无拐点，输出 **2 位相同数字（平调 Level，如 `55`、`33`）**；否则输出 **2 位升降调（如 `35`、`51`）**。
     - **模糊边界提示**：当采样值落在整数分界线 `x.5 ± 0.1` 时，标记为轻微偏移（如 `45 / 55` 交界），避免机械扣分。

#### 模块 4：前端实时提取与可视化展示升级

1. **前端实时算法升级：`AudioWorklet` + YIN/MPM + 个人音域同步**
   - **脱离 `requestAnimationFrame` 采样**：现在 [RealtimeAcousticCanvas.vue](src/components/RealtimeAcousticCanvas.vue) 在 `rAF` 里调 `AnalyserNode.getFloatTimeDomainData`。一旦页面掉帧或显示器是 60Hz/120Hz，帧移就不固定。建议改用 **`AudioWorklet`**（或固定 10ms 步长的环形缓冲）运行 `pitchy` 或 `pitchfinder (YIN)`，保证严格的 10ms 帧率。
   - **前端实时画布直接绑定用户五度音域 `[fLo, fHi]`**：
     进入录音页时，从用户信息读取 `pitchRange {fLo, fHi}`，将 `RealtimeAcousticCanvas` 的纵轴直接设为用户的 **1 度（`fLo`）到 5 度（`fHi`）对数坐标**！这样学生在说话的瞬间，就能看到自己的声音处于自己个人音域的“第几度”，而不是一个飘忽不定的相对窗口。

2. **图表展示效果的 4 项视觉升级（[ToneCurveChart.vue](src/renderers/ToneCurveChart.vue) & [RealtimeAcousticCanvas.vue](src/components/RealtimeAcousticCanvas.vue)）**
   - **五度背景色带 + 赵元任调值徽章（Chao Tone Badge）**：
     在 `ToneCurveChart.vue` 的 Y 轴（1–5 度）上绘制五度五线谱背景参考线（`1: 低`, `2: 半低`, `3: 中`, `4: 半高`, `5: 高`），并在每个音节上方直接显示对比卡片：`目标: ǎ (214)  |  实测: 212 ⚠️ 尾音未扬起`。
   - **置信度/能量编码（借鉴 Shinytone 校正页）**：
     不要用同样粗细的实线画所有帧！
     - **正常浊音（Modal）**：实心平滑蓝线，线宽随该帧能量（RMS dB）在 `2px–4.5px` 之间微调，既有书法般的笔锋呼吸感，又能直观反映字尾音量衰减；
     - **嘎裂/气泡音（Creaky）**：切换为**琥珀色点线（dotted）**，让学生一眼看出哪里是气泡音/压喉音；
     - **静音/断音（Unvoiced Gap）**：严格留白断开，若音节内部异常断音，在断口处画浅红色背景高亮条提示“气息中断”。
   - **声调合成回放（Sonification A/B 对比，直接借用 `tone_py/sonify.py`）**：
     `tone_py/sonify.py` 已经完整实现了 `sonify_f0()`（可以把任意 F0 曲线合成为纯正弦滑音或 `/a/ /i/ /u/` 元音哼鸣声）。在结果页加一个 **“只听音高旋律（哼鸣对比）”** 按钮：剥离声母韵母咬字干扰，先后播放“标准曲线哼鸣声”和“你的曲线哼鸣声”，学生对音高走势的感知会瞬间提升一个数量级。
   - **可切换坐标轴视图**：
     结果页默认展示面向教学的 **“五度值（1–5 度）”**，右上角提供切换按钮：**`[五度制 1-5]  [半音 ST]  [绝对频率 Hz]`**，兼顾普通学习者与专业语音训练需求。

# 基频（F0）提取、异常清洗、五度标音与双轨可视化升级方案

## 一、 核心设计原则：同源同轨（Same-Pipeline Overlay）

**用户录音**与**标准示范录音（默认发音人）**必须走**完全相同的声学提取、异常清洗、分段修剪、等距重采样与个人音域归一化管线**。
- 标准发音人有其自身的参考音域 $[f_{\text{lo}}^{\text{ref}}, f_{\text{hi}}^{\text{ref}}]$；
- 用户有其自身的个人音域 $[f_{\text{lo}}^{\text{user}}, f_{\text{hi}}^{\text{user}}]$；
- 双方各自完成声学清洗与归一化后，在统一的时间轴與五度/半音坐标系中对齐叠加。

---

## 二、 后端基频提取与多候选解算管线

### 1. 信号预处理与双特征同步提取
1. **统一重采样与高通滤波**：
   - 输入音频统一转为 `16000 Hz` 单声道浮点 PCM，峰值归一化至 `-1 dBFS`（保留原始绝对 RMS 偏置供静音门限参考）。
   - 施加 `35 Hz` 二阶巴特沃斯高通滤波器（消除麦克风直流偏置与呼吸喷麦极低频冲击，避免污染低频自相关）。
2. **Praat `To Pitch (filtered ac)` 宽域提取**：
   - 弃用旧版 `To Pitch (ac)`，改用 Praat 6.4+ 的 **`To Pitch (filtered ac)`**（在自相关前对信号做高斯低通滤波，从源头抑制高次谐波与声道第一共振峰 F1 造成的八度误判）。
   - 核心参数设定：
     - `time_step = 0.010`（10 ms 帧移）
     - `pitch_floor = 50.0` Hz（下探至 50 Hz 以覆盖男低音与三声/四声嘎裂段）
     - `pitch_ceiling = 600.0` Hz（覆盖女高音与儿童音域）
     - `max_number_of_candidates = 15`
     - `very_accurate = "yes"`
     - `attenuation_at_top = 0.03`
     - `silence_threshold = 0.04`（抑制清辅音送气段与底噪）
     - `voicing_threshold = 0.50`
     - `octave_cost = 0.055`、`octave_jump_cost = 0.35`、`voiced_unvoiced_cost = 0.14`
3. **同步提取每帧候选集与短时强度（Intensity）**：
   - 遍历 `Pitch` 对象的每一帧 $i$，不仅取选定频率 `f0[i]`，同时提取该帧的前 3 个有声候选 `candidates[i] = [(freq_1, strength_1), (freq_2, strength_2), (freq_3, strength_3)]`。
   - 调用 Praat `To Intensity (50.0, 0.010, "yes")`，用线性插值对齐到 `Pitch` 的时间网格 `t`，得到逐帧能量 `intensity_db[i]`。
   - 计算 5 ms/10 ms 窗长的逐帧过零率 `zcr[i]`（用于后续区分低频嘎裂与高频清擦音）。

## 三、 静音段、嘎裂（气泡音）与音高跳跃的四步清洗流水线

### Step 1：清浊边界修剪与静音段处理（Silence & Unvoiced Handling）
1. **孤立伪有声点剔除**：
   - 扫描原始有声掩码 `voiced = np.isfinite(f0) & (f0 > 0)`，任何连续有声游程长度 `< 2` 帧（即 `< 20 ms`）的孤立点直接置为 `NaN`（消除塞音除阻爆破瞬间的假周期）。
2. **音节内浊音核心区修剪（`trim_to_voiced`）**：
   - 在每個音节（或整段单字录音）的粗略时间边界 $[t_0, t_1]$ 内，不能直接把声母段（清塞音送气、清擦音）算进声调时间轴。
   - 起点锚定在首个**连续 $\ge 3$ 帧（30 ms）有声且 `zcr < 0.20`** 的帧；终点锚定在末个**连续 $\ge 2$ 帧（20 ms）有声**的帧。
3. **协同发音边缘截除（Consonant Perturbation Trimming）**：
   - 声母除阻后最初 15–20 ms 的声带起振常带有受辅音清浊影响的瞬态 F0 尖峰（下冲或上冲）。若浊音段总帧数 $\ge 10$（100 ms），在计算五度调值与曲线斜率时剔除首尾各 1 帧（或首尾各 5% 时长）。
4. **静音断口保留原则**：
   - 音节内部若出现连续 `NaN` 帧（发声中断）：
     - 若断口时长 $\le 30\text{ ms}$（1–3 帧）且前后帧半音差 $< 2.0\text{ ST}$，视为瞬时测量丢失，允许后续插值修补；
     - 若断口时长 $> 30\text{ ms}$，视为真实静音/断气，**严禁跨断口插值**，在输出序列中严格保留 `NaN / null`，前端自然留白断开 (`connectNulls: false`)。

### Step 2：嘎裂 / 气泡音（Creaky Voice）识别与恢复
普通话第三声（214）谷底与第四声（51）句尾极易出现生理性嘎裂（声带松弛、不规则脉冲或双周期振动 Diplophonia），必须将其从“误判无声”或“半频跳变”中拯救出来：
1. **嘎裂拯救窗（Creaky Rescue Pass）**：
   - 对紧邻稳定浊音段内部（缺口 $\le 120\text{ ms}$）或浊音段末尾（后随 $100\text{ ms}$ 内）原本被判为 `unvoiced` 的帧，检查其 `candidates` 中的最强有声候选 $(f_{\text{cand}}, s_{\text{cand}})$：
   - 若满足以下 4 个条件，将其恢复为有声帧并标记 `quality = "creaky"`：
     1. 候选频率 $f_{\text{cand}} \in [42\text{ Hz}, f_{\text{median}} \times 0.85]$（位于该音节中位数之下）；
     2. 候选自相关强度 $s_{\text{cand}} \ge 0.30$（低于常规 0.50 门限，但显著高于噪声）；
     3. 帧能量 `intensity_db[i]` $\ge \max(\text{floor\_db} + 6\text{ dB}, \text{peak\_db} - 22\text{ dB})$；
     4. 帧过零率 `zcr[i] < 0.16`（确保不是清擦音或呼吸气声）。
2. **双周期半频折叠展开（Subharmonic / Period-Doubling Unfolding）**：
   - 嘎裂常表现为声带交替大小周期振动，导致自相关锁在 $f_0 / 2$（低八度）。
   - 对所有低能量帧（`intensity_db < peak_db - 12 dB`）或 `creaky` 帧，计算其与紧邻稳定浊音帧 $f_{\text{anchor}}$ 的比值 $r = f[i] / f_{\text{anchor}}$：
   - 若 $r \in [0.45, 0.55]$（典型半频跳变）：
     - 先检查该帧候选集中是否存在落入 $[0.82 \cdot f_{\text{anchor}}, 1.18 \cdot f_{\text{anchor}}]$ 的候选；若有，直接采用该候选频率；
     - 若无，则将频率修正为 $2 \times f[i]$，同时保留 `quality = "creaky"` 标记。
   - 若该帧确实是连续下滑进入极低频（无阶跃跳变，帧间下降率符合生理极限），则保留其实测低频並标记 `quality = "creaky"`。

### Step 3：生理速率约束的音高跳跃检测与候选重选（复用并强化 `tone_py/inspect.py`）
直接调用并扩展内置 `tone_py.inspect.flag_pitch_jumps()` 的核心算法：
1. **Sundberg 生理速率门限与八度比检测**：
   - 将有声帧序列转换为半音：$ST[i] = 12 \log_2(f_0[i] / 55)$。
   - 计算相邻有声帧（时间差 $\Delta t$ 秒）的每 10 ms 归一化半音变化率：
     $$\Delta ST_{10\text{ms}} = \frac{ST[i] - ST[i-1]}{\Delta t / 0.010}$$
   - 触发跳变标记的条件（满足其一）：
     - 上升速率 $> +1.263\text{ ST}/10\text{ms}$（Sundberg 人类声带最快升调极限）；
     - 下降速率 $< -1.714\text{ ST}/10\text{ms}$（Sundberg 人类声带最快降调极限）；
     - 频率比 $f_0[i] / f_0[i-1] > 1.95$ 或 $< 0.51$（八度倍频/半频跳变）。
   - **异常侧判定与 Carryover 双向扩展**：
     - 比较 $ST[i-1]$ 与 $ST[i]$ 谁离当前音节的中位数半音 $ST_{\text{median}}$ 更远，将旗标打在**偏离中位数更远的那一帧**；
     - 从该异常帧向前后两侧做 Carryover 扩展：只要后续相邻帧与该异常帧的差距在 $1.5 \times \text{threshold}$ 以内（即持续停留在错误八度平台上），整段连续帧全部标记为 `flagged_jump = True`。
2. **自动纠偏三步策略（替代一刀切拒画）**：
   对每一段连续的 `flagged_jump` 异常区间（设长度为 $L$ 帧）：
   - **策略 A（Praat 次优候选替换）**：遍历异常区间内各帧的 Top-3 候选，寻找与区间两侧正常锚点半音线性插值期望值 $ST_{\text{expected}}[k]$ 差距 $< 2.5\text{ ST}$ 的候选；若找到，直接替换。
   - **策略 B（倍频/半频代数折算）**：若 `×2` 或 `÷2`（即 $\pm 12\text{ ST}$）后与两侧正常锚点的差距 $< 2.5\text{ ST}$，则执行代数折算。
   - **策略 C（短缺口抹除与保形插值）**：若策略 A/B 均不满足：
     - 当异常块长度 $L \le 4$ 帧（$\le 40\text{ ms}$）时，将其置为 `NaN`；
     - 当 $L > 4$ 帧时，置为 `NaN` 并作为断口保留。
3. **更新可靠性判定（`reliable`）**：
   - 经过上述纠偏后，重新统计剩余未修复跳变密度 `residual_jump_density`。
   - 仅当有效有声帧 $< 8$ 帧（80 ms）或纠偏后 `residual_jump_density > 0.20` 时才判为不可靠，大幅降低误拒画率。

### Step 4：半音域保形插值与 Savitzky-Golay 平滑
1. **短缺口保形插值（仅限 $\le 30\text{ ms}$ 内部缺口）**：
   - 在半音域 $ST$ 上，仅对浊音段内部长度 $\le 3$ 帧的 `NaN` 缺口使用 **PCHIP（Piecewise Cubic Hermite Interpolating Polynomial，`scipy.interpolate.PchipInterpolator`）** 插值（PCHIP 具有严格单调性，绝不会在拐点处产生三次样条那样的过冲振荡）。
   - 长度 $> 3$ 帧的缺口保持 `NaN` 不动。
2. **分段 Savitzky-Golay 滤波**：
   - 对每一段连续非 `NaN` 的有声游程（长度 $M$）：
     - 若 $M \ge 7$：在半音域应用 `scipy.signal.savgol_filter(window_length=7, polyorder=2)`；
     - 若 $5 \le M < 7$：应用 `savgol_filter(window_length=5, polyorder=2)`；
     - 若 $3 \le M < 5$：应用 3 点中值滤波；
   - 二次多项式 Savitzky-Golay 能在滤除微观声带抖动（Jitter）的同时，**零衰减地保留第三声（214）谷底与峰值的曲率极值**（普通移动平均或过强 EMA 会把三声谷底削平）。
3. **等距重采样（调用 `tone_py/resample.py` 的 `resample_f0_equal` 规则）**：
   - 将每个音节修剪后的时间轴归一化到 $t_{\text{norm}} \in [0, 1]$，在 $N = 21$ 个等距点（步长 0.05）或 $N = 50$ 个点上重采样：
   - 严格遵循 Praat `Get value at time` 铁律：定位采样点两侧最近的原生帧 `near` 和次近帧 `far`：
     - 若 `near` 为 `NaN`（无声）：输出 `null`（绝不跨静音段捏造数据）；
     - 若 `near` 有声、`far` 无声：直接取 `near` 的值；
     - 若两侧均有声：在半音域线性插值，并携带 `near` 帧的 `intensity`（归一化到 $[0, 1]$）与 `quality`（`"modal" | "creaky"`）。

## 四、 说话人个人音域（Speaker Pitch Range）与五度标音实现

### 1. 三级个人音域模型 $[f_{\text{lo}}, f_{\text{hi}}]$
人耳对声调高低的感知是严格对数（半音）尺度的。定义个人五度音域下界 $f_{\text{lo}}$（对应五度底线）和上界 $f_{\text{hi}}$（对应五度顶线）：

1. **Level 1：主动标定音域（Calibration）**
   - 标定语料需覆盖高低极限（包含第一声/第四声高音峰与第三声/第四声尾低音谷）。
   - 对标定录音经上述四步清洗后的有声帧（剔除未折叠的极低能量异常帧），在对数域 $\ln(f_0)$ 取 **P5 与 P95 分位数**，并在半音域向外扩展 $1.0\text{ ST}$（约 6%）：
     $$\ln f_{\text{lo}} = P_5(\ln f_0) - \frac{1.0}{12}\ln 2, \quad \ln f_{\text{hi}} = P_{95}(\ln f_0) + \frac{1.0}{12}\ln 2$$
   - 最小跨度守卫：若总跨度 $12 \log_2(f_{\text{hi}} / f_{\text{lo}}) < 6.0\text{ ST}$（说明用户标定时用平调念经，未拉开高低音），则以中位数 $ST_{\text{med}}$ 为锚点，强制撑开到标准生理跨度 $[ST_{\text{med}} - 6\text{ ST}, ST_{\text{med}} + 4\text{ ST}]$。

2. **Level 2：滚动稳健峰谷音域（Rolling Robust Peak-Valley FOR，核心推荐）**
   - 直接吸收 `tone_py/chao.py` 中 Zhu (1999) / Xu & Zhang (2024) 的 **Robust FOR** 与 `tone_py/normalise.py` 的 **两级加权统计** 思想：
   - 收集该用户历史有效音节（加上本次录音音节）：
     - **高音锚点集 $\mathcal{P}$**：所有目标为 1 声、2 声、4 声音节的段内 P90 峰值（对数 Hz）；
     - **低音锚点集 $\mathcal{V}$**：所有目标为 3 声、4 声音节的段内 P10 谷值（对数 Hz）。
   - 当 $|\mathcal{P}| \ge 3$ 且 $|\mathcal{V}| \ge 3$ 时，使用稳健中位数与 MAD（防止单次破音污染）计算上下界：
     $$\ln f_{\text{hi}} = \text{median}(\mathcal{P}) + 1.2 \times \text{MAD}(\mathcal{P})$$
     $$\ln f_{\text{lo}} = \text{median}(\mathcal{V}) - 1.2 \times \text{MAD}(\mathcal{V})$$
   - 这一方法彻底解决了“用户连练 10 个第一声，普通分位数把高音区当成全部音域”的顽疾。

3. **Level 3：单次未标定冷启动（Tone-Aware Single-Utterance Fallback）**
   - 当用户无标定、无历史记录，且当前只录了一个单音节或窄起伏音频（段内 P95/P5 跨度 $< 4.5\text{ ST}$）时，**结合目标调号 `target_tone` 反推个人音域中心**：
     - 设当前音节实测中位数半音为 $ST_{\text{obs}}$，标准普通话说话人自然五度音域总跨度取 $W = 10.0\text{ ST}$（1 度 = $2.0\text{ ST}$）：
     - 若当前是 **1 声（55，高平）**：$ST_{\text{obs}}$ 理论上位于 4.5 度附近，故设 $ST_{\text{hi}} = ST_{\text{obs}} + 1.5\text{ ST}$，$ST_{\text{lo}} = ST_{\text{hi}} - 10.0\text{ ST}$；
     - 若当前是 **3 声（214/21，低降升）**：$ST_{\text{obs}}$ 理论上位于 2.0 度附近，故设 $ST_{\text{lo}} = ST_{\text{obs}} - 2.0\text{ ST}$，$ST_{\text{hi}} = ST_{\text{lo}} + 10.0\text{ ST}$；
     - 若当前是 **2 声（35）或 4 声（51）或未知**：以 $ST_{\text{obs}}$ 为 3.2 度中心，设 $ST_{\text{lo}} = ST_{\text{obs}} - 5.5\text{ ST}$，$ST_{\text{hi}} = ST_{\text{obs}} + 4.5\text{ ST}$。

### 2. 连续五度值与赵元任离散五度数字（Chao Tone Numerals）计算
1. **三种纵轴坐标同步产出**：
   对每个重采样点 $f_0(t)$，同时支持三种坐标映射（供前端一键切换）：
   - **五度制 T 值（Continuous T-value $\in [1.0, 5.0]$ 或 $[0.0, 5.0]$）**：
     - 连续比例值（对齐现有 $[0, 5]$ 坐标系）：
       $$T(t) = \text{clip}\left(5.0 \times \frac{\ln f_0(t) - \ln f_{\text{lo}}}{\ln f_{\text{hi}} - \ln f_{\text{lo}}}, 0.0, 5.0\right)$$
     - 传统赵元任参考线值（$[1, 5]$）：
       $$D(t) = \text{clip}\left(1.0 + 4.0 \times \frac{\ln f_0(t) - \ln f_{\text{lo}}}{\ln f_{\text{hi}} - \ln f_{\text{lo}}}, 1.0, 5.0\right)$$
   - **个人中心归一化半音（Speaker-normalised Semitone, `f0_st`）**：
     $$ST_{\text{rel}}(t) = 12 \log_2\left(\frac{f_0(t)}{\sqrt{f_{\text{lo}} \cdot f_{\text{hi}}}}\right)$$
   - **绝对频率（Hz）**：平滑后的 $f_0(t)$。

2. **离散五度标调数字提取（直接调用 `tone_py.chao.contour_to_chao` 与 `classify_contour`）**：
   - 将每个音节归一化时间 $t \in [0, 1]$ 上的平滑曲线传入 `contour_to_chao`（采样区间取去除头尾辅音微扰后的有效段）：
   - **端点与拐点判定**：
     - 取起点 $t_{\text{start}} = 0.05$ 与终点 $t_{\text{end}} = 0.95$ 的五度值 $D_{\text{start}}, D_{\text{end}}$；
     - 在内部区间 $t \in [0.15, 0.85]$ 搜索极大值 $D_{\max}$ 与极小值 $D_{\min}$；
     - 若 $\min(D_{\text{start}}, D_{\text{end}}) - D_{\min} \ge 0.5$（凹拐点显著）：提取 3 位调值 `[D_start, D_min, D_end]`；
     - 若 $D_{\max} - \max(D_{\text{start}}, D_{\text{end}}) \ge 0.5$（凸拐点显著）：提取 3 位调值 `[D_start, D_max, D_end]`；
     - 否则提取 2 位调值 `[D_start, D_end]`。
   - **取整规则**：
     - Interval 模式：`digit = clamp(ceil(T_val), 1, 5)`（将 $(0, 5]$ 等分为 $(0,1], (1,2], (2,3], (3,4], (4,5]$ 五个区间，对应 1–5 度）；
     - Reference-line 模式：`digit = clamp(round(D_val), 1, 5)`；
   - 调用 `classify_contour(chao_str)` 得到调型分类（`"high level"`, `"rising"`, `"dipping"`, `"falling"` 等），用于现象诊断规则。

## 五、 标准示范录音的同算法叠加与哼鸣合成（Sonification）

### 1. 标准示范曲线同管线生成与对齐叠加
- 对标准示范音频（默认发音人录音）运行与用户录音**完全一致**的 `extract_f0`（`filtered ac` + 异常清洗 + Savitzky-Golay 平滑 + `trim_to_voiced` + 21 点等距重采样）。
- 标准发音人的五度归一化使用该标准发音人自身的稳健音域 $[f_{\text{lo}}^{\text{ref}}, f_{\text{hi}}^{\text{ref}}]$（由该发音人全库示范音频按 Level 1/Level 2 预先统计得出）。
- **叠加对齐方式**：
  - 在归一化音节时间轴（每个音节内部 $t \in [0, 1]$，或按标准音节时长等比缩放的时间轴）上，将**用户曲线**与**标准发音人实测曲线**同屏叠加渲染。
  - 若切换到 `[绝对频率 Hz]` 视图，同时绘制各自真实的 Hz 曲线；若在 `[五度制]` 或 `[相对半音 ST]` 视图，两条曲线均已消除性别/天生嗓音高低差异，纯粹对比声调走势与调域饱满度。

### 2. 音高旋律声化试听（Sonification A/B 对比，接入 `tone_py/sonify.py`）
直接调用内置的 `tone_py.sonify.sonify_f0()`，为用户提供剥离咬字干扰的纯音高听觉对比：
- 输入：每个音节清洗后的 `f0_hz` 序列与对应的 `intensity_db` 包络。
- 参数：`fs = 16000`，`source = "vowel"`（使用 `sonify.py` 内置的 Klatt 三共振峰级联合成器合成中性元音 `/a/` 哼鸣声，比刺耳的纯正弦波更自然悦耳）或 `"complex"`（1/h 谐波复合音），传入 `intensity` 使合成音自带真实的起音与收尾包络。
- 产出两条音频流（Base64 WAV 或端点流）：
  1. **标准示范音高哼鸣**（可选：将标准曲线映射到用户本人的中位数音高 $f_{\text{med}}^{\text{user}}$ 上合成，让学生听到“用我自己的嗓音读出标准声调是什么感觉”！即 `f0_target_in_user_voice = exp(ln(f_lo_user) + T_ref / 5 * (ln(f_hi_user) - ln(f_lo_user)))`）；
  2. **用户实测音高哼鸣**。

## 六、 前端实时提取与图表视觉渲染实现

### 1. 前端实时提取升级（[realtimeAcoustics.ts](src/utils/realtimeAcoustics.ts) & [RealtimeAcousticCanvas.vue](src/components/RealtimeAcousticCanvas.vue)）
1. **固定步长环形缓冲（解耦渲染帧率与分析帧率）**：
   - 使用 `AudioWorkletNode`（或基于采样计数的环形缓冲区）以严格固定的 **10 ms 步长（48kHz 下每 480 个采样点）** 触发一次 2048 点窗口的 MPM（NSDF）计算，不再受显示器 60Hz/144Hz 或主线程卡顿影响。
2. **实时双门限与 Sundberg 跳变门控**：
   - 主门限：`clarity >= 0.82` 且 `rms >= 0.012`。
   - 嘎裂延续门限：若前 3 帧处于稳定有声状态，且当前帧 `rms >= 0.008`、`clarity >= 0.55`、频率位于当前个人音域下半区（`< centerSt`），则允许延续为 `creaky` 有声帧，避免学生发第三声谷底时实时曲线突然断掉。
   - 实时防八度跳变：若当前帧与上一有声帧的半音差 $|\Delta ST| > 2.0\text{ ST}/10\text{ms}$：
     - 若差距接近 $\pm 12\text{ ST}$（即 $[10.5, 13.5]\text{ ST}$），立即执行 $\mp 12\text{ ST}$ 八度折回；
     - 否则将该帧暂挂入 3 帧观察缓冲，确认连续 3 帧均在新音高平台后才更新轨迹，彻底消灭实时画面上的单帧飞线。
3. **实时纵轴绑定个人音域 `[fLo, fHi]`**：
   - 若用户已有标定或历史自适应音域 $[f_{\text{lo}}, f_{\text{hi}}]$，将其直接传入 `AdaptivePitchWindow`：
     - 窗口的 1 度线直接锚定 $\text{hzToSemitone}(f_{\text{lo}})$，5 度线锚定 $\text{hzToSemitone}(f_{\text{hi}})$，画布纵轴范围设为 $[ST(f_{\text{lo}}) - 2\text{ ST}, ST(f_{\text{hi}}) + 2\text{ ST}]$。
   - 若无个人音域，才启用动态均值自适应。这保证了**录音时的五度引导带与结果页的五度坐标 100% 物理对齐**。

### 2. 结果页图表展示升级（[ToneCurveChart.vue](src/renderers/ToneCurveChart.vue)）
*（严格遵守约束：不在音节上方显示对比卡片，不在断口处画浅红色气息中断背景条）*

1. **标准录音曲线与用户曲线同屏叠加**：
   - **标准示范曲线**：采用经过相同算法从默认发音人音频提取的真实曲线，以平滑虚线（或带半透明 0.3 度包络带的参考轨迹）绘制。
   - **用户实测曲线**：叠加在同一坐标系上。
2. **模态嗓音（Modal）与嘎裂/气泡音（Creaky）分段样式**：
   - 将用户曲线拆分为两条同色系互补的 ECharts Series（共享图例 `"我的曲线"`）：
     - **正常浊音段（`quality === "modal"`）**：实心平滑曲线（`lineStyle: { type: 'solid', width: 3.5 }`）；可选根据每帧 `intensity` 动态映射象征性的点大小或透明度，体现字尾自然衰减。
     - **嘎裂/气泡音段（`quality === "creaky"`）**：琥珀色/深青色点状虚线（`lineStyle: { type: 'dotted', width: 3 }`）与正常段无缝衔接，直观呈现三声谷底或四声尾的低频气泡音，既不断线也不与正常嗓音混淆。
   - **静音与清音段（`v === null`）**：保持 `connectNulls: false`，自然留白断开，不做任何跨静音连线或额外背景色块渲染。
3. **三种坐标轴视图一键切换**：
   - 在图表组件顶部提供维度切换控件：`[五度值 (0-5)]` | `[相对半音 (ST)]` | `[频率 (Hz)]`：
     - **五度值视图（默认）**：Y 轴 `0–5`，刻度标注 `1 (低)`, `2 (半低)`, `3 (中)`, `4 (半高)`, `5 (高)` 五条水平参考网格线；
     - **相对半音视图**：Y 轴 `-8 ST ~ +8 ST`，以说话人个人音域中心为 `0 ST` 基准线；
     - **绝对频率视图**：Y 轴采用对数坐标（`type: 'log'` 或半音等距刻度映射 Hz 标签），同时展示用户真实 Hz 与标准发音人真实 Hz。
4. **哼鸣旋律 A/B 试听控件**：
   - 在图表旁提供 **“听标准音高旋律”**、**“听我的音高旋律”**（以及可选的 **“用我的音高听标准旋律”**）播放按钮，点击后播放后端 `tone_py.sonify` 合成的音频，并在图表上同步推进时间游标。
